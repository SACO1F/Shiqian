## 1. 项目目标与决策边界

### 1.1 用户明确提出的需求

1. 可以对本地文件或图片进行标注。
2. 同一个文件可以拥有多个标注。
3. 工作时可以通过标注找到想要的文件。
4. 界面交互合理，设计优雅。

### 1.2 产品定位

一个以标签为核心的本地文件工作台，让用户按照项目、用途、内容特征和工作状态来组织与查找资料。

核心使用场景：用户记不清文件名和保存位置，但记得“上次品牌项目里那张适合做首页的极简参考图”，仍然能逐步缩小范围并找到文件。

产品主流程：

**加入文件 → 添加标签或备注 → 组合筛选与预览 → 打开原文件使用。**

### 1.3 本文采用的建议默认值

以下是让开发方案具体化的工作假设，可以在开发前调整。

| 决策项 | 建议默认值 | 状态 |
| --- | --- | --- |
| 面向用户 | 个人使用，优先覆盖工作资料与图片素材整理 | 建议 |
| 首发平台 | Windows 11 x64；其他系统后续扩展 | 建议，兼容范围待确认 |
| 文件管理方式 | 引用原文件，不搬动、不复制、不向原文件写入标签 | 建议 |
| 首版标注形式 | 文件级标签与纯文本备注 | 建议 |
| 数据位置 | 本机应用数据目录，支持用户主动备份 | 建议 |
| 网络依赖 | P0 核心功能离线可用，无账号和云端依赖 | 建议 |
| 技术方案 | Tauri 2 + React + TypeScript + Rust + SQLite | 建议，须通过技术验证 |
| 智能集合 | P1；概念界面中的入口不构成 P0 范围承诺 | 建议 |

### 1.4 成功标准

- 用户能在不改变原有目录结构的情况下开始整理。
- 同一文件可按多个不同维度被找到。
- 批量整理不需要逐个打开编辑窗口。
- 文件改名、移动或暂时离线后，标注记录仍有可恢复的去向。
- 保存失败、文件不可用、预览不支持等状态表达清楚。
- 标注成果可导出备份，并在另一安装实例中恢复。

## 2. 用户场景与术语

### 2.1 典型场景

| 场景 | 用户操作 | 预期价值 |
| --- | --- | --- |
| 整理参考素材 | 加入图片，标注“品牌升级、极简、参考图” | 跨目录找回相关素材 |
| 整理项目资料 | 给合同、需求文档、会议记录添加相同项目标签 | 以项目为单位组织不同格式文件 |
| 批量处理下载资料 | 多选文件，一次添加用途标签 | 减少整理成本 |
| 记录使用上下文 | 在备注写下“布局可用，配色需要调整” | 保留文件为何值得收藏的原因 |
| 查找并调用文件 | 组合筛选，预览，再打开原文件 | 从查找直接进入工作 |
| 迁移或恢复 | 导出标注备份，在新电脑恢复并重新关联路径 | 保留长期整理成果 |

### 2.2 术语定义

| 术语 | 定义 |
| --- | --- |
| 原文件 | 用户磁盘上实际保存的文件 |
| 文件记录 | 应用中对原文件的引用，具有独立、稳定的内部 ID |
| 标签 | 可重复用于不同文件的短文本分类；文件与标签为多对多关系 |
| 备注 | 附属于单个文件记录的纯文本说明 |
| 文件库 | 本机当前管理的全部文件记录；P0 只提供一个文件库 |
| 待整理 | 没有任何标签的文件记录；有备注但无标签仍属于待整理 |
| 收藏 | 独立的布尔属性，不占用标签名称 |
| 智能集合 | 保存一组查询条件，展示符合条件的实时结果，P1 实现 |
| 加入 | 在应用中创建引用与元数据，不表示复制原文件 |
| 移除 | 从文件库移除记录，不表示删除原文件 |
| 重新关联 | 将已有文件记录及其标注连接到用户指定的文件位置 |

示例：`品牌首页-参考.png` 可以同时拥有“品牌升级”“首页参考”“极简”“待采用”四个标签，以及一条备注“留意标题留白和图片比例”。

P0 标签全部是普通标签。诸如“待处理”和“已完成”不会自动互斥，应用也不会擅自删除旧标签。带互斥规则的状态字段属于后续设计。

- **P0：首版必需。** 构成可使用、可恢复的核心流程。

- **P2：后续探索。** 内容识别、复杂标注与跨设备能力。

建议初始侧栏宽约 180 px、详情栏宽约 300 px，文件区自适应。详情栏可关闭。窗口变窄时折叠侧栏文字或将详情切换为抽屉，保持文件区可用。

首版验收建议覆盖 960×640、1280×800、1920×1080，以及 Windows 100%、125%、150% 缩放。小于最低窗口尺寸时采用系统最小尺寸约束；本规格不承诺移动端布局。

### 4.3 视觉原则

- 使用中性色和一个主强调色，颜色服务于选中、焦点和状态。
- 文件内容优先，网格图片默认完整适配预览区，避免关键内容被裁切。
- 文件卡片显示文件名、类型及最多三个标签；其余显示“+N”。
- 文件名过长时允许两行截断，悬停和键盘聚焦可查看完整名称。
- 路径、详细属性和全部标签放入详情区域。
- 标签不默认使用随机彩色；必要的状态同时配合文字，不能只依赖颜色。
- 深浅主题跟随系统，也允许用户手动覆盖。
- 交互控件必须有明确的焦点状态；禁用操作需要说明当前不可用原因。

### 4.4 列表与网格

网格适合图片素材，列表适合项目文档。两种视图共享同一查询、排序与选择模型。

列表默认列：文件名、标签、类型、修改时间、文件可用性。路径可作为可选列。列表不默认展示完整备注。

切换视图保留当前筛选与选择；排序相同的结果应能定位到同一文件。每个内置范围分别记住视图偏好。

### 4.5 键盘与选择规则

| 操作 | 预期行为 |
| --- | --- |
| 单击文件 | 选中文件，在详情区展示 |
| 双击文件 | 请求用系统默认程序打开 |
| Ctrl + 单击 | 增减多选项 |
| Shift + 单击 | 选择当前排序下的连续区间 |
| Ctrl + A | 文件区聚焦时选择当前已加载结果，不含尚未加载结果；显示数量 |
| Ctrl + F | 聚焦搜索框 |
| 空格 | 文件区聚焦时打开或关闭快速预览 |
| Enter | 文件区聚焦且仅选中一个文件时打开原文件 |
| Escape | 优先关闭浮层；无浮层时取消多选 |
| Ctrl + Z | 非文本编辑状态下撤销最近一次可撤销操作 |

输入框中保留系统标准文本编辑快捷键，不触发文件打开、全选文件或标签撤销。中文输入法组合输入结束前不提交标签，也不启动半成品关键词搜索。

## 5. 功能行为规格

### 5.1 F01：加入文件与文件夹

支持通过选择器或拖放加入常规文件。加入文件夹时默认包含子文件夹，用户可取消递归。文件夹作为扫描入口，不作为 P0 可标注实体。

处理规则：

1. 路径由本地服务校验，记录原始显示路径和用于比较的规范化路径键。
2. 首先创建可搜索的文件记录，缩略图排入后台任务，不阻塞加入完成。
3. 相同路径重复加入时复用已有记录和标注，不产生重复文件记录。
4. 不同路径的相同内容文件分别保留；P0 不按内容自动合并。
5. 同一路径被新文件占用且能识别出身份变化时，标记关联异常，不静默继承旧文件的标注。
6. 不跟随目录符号链接或重解析点递归扫描，避免循环与越界；明确选择的普通文件单独处理。
7. 默认跳过隐藏和系统文件；界面说明跳过数量。应用自己的数据库、缓存和备份临时文件始终排除。
8. 允许逐项失败。无权限、消失、损坏的项目单独列出，不中断其他文件加入。
9. 取消时停止发现新项目并完成已开始的安全提交；已加入的记录保留。
10. 中断后重新加入相同来源必须幂等；P0 不要求自动恢复未完成扫描任务。

进度至少显示：已发现、已处理、新增、已存在、跳过、失败。扫描总数未知时显示计数与活动状态，不伪造百分比。

### 5.2 F02：标签创建、重命名与删除

- 标签名去除首尾空白，禁止空值和换行，长度 1～40 个用户可见字符。
- 名称规范化建议采用 Unicode NFC 与大小写折叠，用于唯一性比较；显示值保留用户写法。
- 不自动将简繁中文、全半角或不同词语视为同义词。
- 输入时优先匹配已有标签，匹配不到时展示“创建标签”。
- 建议列表按最近使用、使用次数、名称排序；排序规则保持稳定。
- 重命名修改标签实体，所有关联文件同步显示新名称。
- 重命名目标与已有标签冲突时拒绝覆盖并说明原因；合并属于 P1。
- 删除标签会移除关联关系，不影响文件或备注；操作前显示影响文件数，并支持会话内撤销。
- 未被使用的标签仍保留，便于后续使用；不自动清理用户创建的分类。

### 5.3 F03：多标签与批量编辑

同一文件和同一标签只能有一条关联，重复添加视为成功且不产生重复数据。

批量编辑区将标签标为“全部拥有”“部分拥有”“均未拥有”。“添加到全部”和“从全部移除”是明确操作，不把混合状态直接解释成删除。

一次批量标签修改在一个数据库事务中完成。任一记录校验失败时整体回滚，界面保留选择并提示重试。后台文件暂时不可用不影响修改其本地标注。

撤销记录保存实际变化的关联集合。例如对部分已有标签的文件批量添加后撤销，只撤销本次新增的关联。

### 5.4 F04：备注

P0 每个文件一条纯文本备注，建议限制为 10,000 个用户可见字符。不支持富文本、附件或渲染备注中的 HTML。

编辑暂停约 500 ms 后自动保存；切换文件、关闭详情或关闭窗口前触发未完成保存。界面区分“保存中”“已保存”“保存失败”。

保存失败时保留按文件 ID 绑定的草稿，不允许切换文件后把草稿写入其他文件。恢复可写状态后可以重试；存在未保存内容时关闭窗口需明确告知。

输入与保存请求都携带文件版本号，旧请求不能覆盖新内容。选择变化、异步查询和列表刷新不能打断输入法组合输入或重置光标。

### 5.5 F05：搜索与筛选语义

#### 搜索范围

P0 文本搜索覆盖：文件名、文件关联的标签名和备注。文件路径通过独立目录条件筛选，不默认混入全文匹配。文件正文、图片内文字、拼音和语义相似度不在 P0 范围内。

关键词去除首尾空白，按空白拆分为词项；每个词项必须至少匹配上述任一字段，多个词项之间为“且”。中文采用字面子串匹配，不承诺分词召回。

关键词中的百分号、下划线、引号和反斜杠按普通字符处理，不能改变查询语义。查询使用参数绑定，不能拼接未经处理的输入。

#### 标签逻辑

| 条件 | 含义 |
| --- | --- |
| 包含全部 A、B | 文件同时拥有 A 与 B |
| 包含任一 A、B | 文件拥有 A 或 B |
| 排除 C、D | 文件不能拥有 C，也不能拥有 D |
| 包含列表为空 | 不施加包含标签限制 |
| 排除列表为空 | 不施加排除标签限制 |

总结果为：**当前范围 ∩ 关键词条件 ∩ 包含标签条件 ∩ 排除标签条件 ∩ 类型条件 ∩ 修改时间条件 ∩ 目录条件 ∩ 可用性条件**。

同一个标签不能同时出现在包含和排除列表。用户把标签改为另一角色时从原列表移除，并即时更新条件块。

多个类型之间为“或”；不同筛选维度之间为“且”。目录包含子目录时使用真实目录边界，不能把 `资料` 的字符串前缀误匹配为 `资料旧版`。

时间条件默认针对原文件修改时间，界面明确标为“修改时间”。用户输入的结束日期包含整天，内部转换为下一天起始时刻的开区间；日期按本机用户时区解释。

#### 结果行为

- 所有当前条件可见、可单独移除，并提供清空筛选。
- 无结果时建议减少条件，不自动放宽用户选择。
- 同名文件显示父目录作为区分信息。
- 默认按加入时间倒序，可改为文件名、修改时间；以内部 ID 作为稳定的最终排序项。
- 每页建议 100 条，虚拟化渲染；返回结果总数和下一页游标。
- 每个查询携带请求序号，迟到的旧结果不覆盖新查询。
- 筛选变化清空多选。当前单选若仍可见则保留，否则选中首项或展示空详情。
- 不可用文件默认仍可出现在全部文件的搜索结果中，显示可用性标记。

### 5.6 F06：格式支持与预览

| 类型 | P0 管理与标注 | P0 预览 | 降级行为 |
| --- | --- | --- | --- |
| JPEG、PNG、WebP | 支持 | 缩略图、放大、适合窗口，正确处理方向信息 | 解码失败显示原因，允许外部打开 |
| PDF | 支持 | 首页缩略图与首页放大 | 加密或损坏时显示占位，允许外部打开 |
| TXT、Markdown | 支持 | 纯文本预览，最多读取前 200 KiB 并提示截断 | 编码不支持时提供外部打开 |
| DOCX、XLSX、PPTX | 支持 | 类型图标和文件属性 | 用系统默认程序打开 |
| SVG、HTML | 支持 | 类型图标；P0 不直接执行或嵌入原内容 | 用外部程序打开 |
| 其他常规文件 | 支持 | 类型图标和基础属性 | 根据系统关联程序处理 |

PDF 多页阅读、动图播放、视频播放和 Office 内容预览属于后续增强，不作为 P0 验收要求。

缩略图是可删除、可重建的缓存。缓存键至少包含文件 ID、内容版本、尺寸和渲染器版本。相同路径的内容变化后不能永久显示旧缩略图。

可见文件优先生成缩略图；后台任务限制并发。图片预览建议设置 100 MB 编码大小与 40 MP 解码像素的初始上限，超过时降级并提示“文件过大，使用外部程序打开”。这些上限属于可调参数，须通过技术验证确定。

### 5.7 F07：原文件操作

- 打开前检查最新可用性，然后使用操作系统的默认文件关联打开。
- 在文件夹中显示应定位并尽可能选中原文件；父目录不可达时返回明确错误。
- 复制路径复制完整路径，提供短暂完成反馈。
- 本地服务负责从文件 ID 解析路径，前端不能提交任意 shell 命令。
- P0 不提供原文件删除、移动或内容修改入口。

### 5.8 F08：内置范围

| 范围 | 查询条件 |
| --- | --- |
| 全部文件 | 未移除的全部文件记录 |
| 待整理 | 未移除且没有标签的文件记录 |
| 已收藏 | 未移除且收藏状态为真 |
| 最近加入 | 全部未移除记录，按加入时间倒序 |
| 不可用文件 | 未移除，且当前状态为 missing、offline 或 inaccessible |

切换内置范围时清空本次临时筛选，避免隐藏条件；保留该范围的视图偏好。后续如改为记住每个范围的筛选，必须另行更新交互规格与测试。

在待整理范围给文件添加第一个标签后，该文件自然离开结果；界面给出轻量反馈并将选择移到下一项。

### 5.9 F09：文件可用性与重新关联

文件可用性和预览状态分开维护，避免把“不能生成预览”误报为“文件不存在”。

| 文件可用性 | 含义 | 界面行为 |
| --- | --- | --- |
| unchecked | 尚未完成本轮检查 | 保留已知信息，后台检查 |
| available | 路径可访问且关联无异常 | 正常操作 |
| missing | 父级存储可达，但目标文件不存在 | 保留标注，提供重新关联 |
| offline | 可以判断所属卷或网络位置暂不可达 | 标记暂不可用，提供重试 |
| inaccessible | 权限、占用或其他访问错误 | 显示具体原因与重试 |

不能可靠判断磁盘离线时使用一般访问错误，不凭一次失败推断文件已删除。

P0 在启动后异步检查已记录位置；用户手动刷新、打开或预览时检查目标文件。优先处理可见项目，避免启动时等待全库检查。P0 不承诺实时发现应用外部发生的移动。

重新关联流程：

1. 用户从不可用记录选择“重新关联”。
2. 选择新位置；展示旧文件信息与新文件信息。
3. 若身份无法确认，明确提示“将原标注关联到所选文件”，由用户确认。
4. 新位置若已被另一条有效记录占用，拒绝覆盖并引导查看已有记录；P0 不自动合并。
5. 在事务中更新路径与身份信息，保留内部 ID、标签、备注、收藏和加入时间。
6. 使预览缓存失效，重新检查文件；保留可供撤销的旧关联信息。

P1 才引入目录监听与可靠的自动关联。平台文件标识、内容指纹等都只是证据，不能仅凭文件名、大小或修改时间自动认定为同一文件。跨盘复制、多个相同内容副本与不确定匹配应交给用户选择。

### 5.10 F10：移除与撤销

“从文件库移除”只修改应用记录。多选时显示影响数量，不能调用原文件删除 API。

首版采用数据库软移除：记录 `removed_at` 并从常规查询中排除，保留标注便于撤销。再次加入相同文件时恢复该记录；若检测到同路径文件身份变化，必须先解决关联异常。

会话内保留最近 20 次可撤销操作：标签添加和移除、标签重命名和删除、收藏变更、记录移除、手动重新关联。备注由文本编辑撤销及草稿机制处理，不进入应用级标签撤销队列。

撤销在事务中执行，并验证目标版本。后续变更已使逆操作不再安全时，说明不能自动撤销，不能覆盖新数据。退出应用清空会话撤销栈；数据库升级和整库恢复也清空该栈。

### 5.11 F11：备份与恢复

P0 提供“导出标注备份”和“从备份恢复”，备份原文件不在范围内。界面必须说明备份包含标注和路径引用，原文件需要用户另行保存。

建议备份扩展名为 `.sqtagbackup`，内部是以下内容的归档：

| 内容 | 用途 |
| --- | --- |
| `manifest.toml` | 备份格式版本、应用版本、数据库版本、创建时间和文件库 ID |
| `metadata.sqlite` | 一致性的文件记录、标签、关联、备注及必要偏好快照 |
| `checksums.sha256` | 检测意外损坏；不作为可信来源认证 |

缩略图与临时任务不放入默认备份，可以重新生成。P0 备份不加密，导出界面说明其中含有文件路径和备注。

运行中的数据库采用 SQLite Online Backup API 或经验证的一致性快照方案。不要仅复制正在写入的数据库主文件，尤其不能遗漏尚在日志中的数据。依据：[SQLite Online Backup API](https://www.sqlite.org/backup.html)。

恢复采用“替换当前文件库”，P0 不做两份文件库的合并。流程必须包含：

1. 读取并校验备份格式、大小限制、内容路径和校验和，禁止归档内容写出临时目录。
2. 在临时位置验证数据库完整性、外键和版本；对支持的旧版本在副本中迁移。
3. 展示备份日期、文件数和标签数，说明原文件不会被复制。
4. 用户确认后，先创建当前库的恢复前备份；创建失败则停止替换。
5. 暂停写入任务、完成未保存内容处理、关闭数据库连接，执行可回滚切换。
6. 新库成功打开并验证后才标记恢复完成；失败则回滚到恢复前数据库。
7. 异步检查路径。迁移电脑后不可达的文件进入重新关联流程，不删除标注。

恢复过程记录磁盘上的切换状态，保证进程中断后下次启动能够选择完整的新库或旧库，而不是半完成文件。

## 6. 本地数据模型

### 6.1 设计原则

- 文件内部 ID 独立于文件路径，移动或重新关联不改变 ID。
- 文件与标签通过关联表表达多对多关系。
- 原始展示文本与用于搜索、比较的规范化文本分开保存。
- 原文件是文件内容的来源；数据库是用户标注的来源；缓存不能成为唯一数据来源。
- 数据库只在本地服务中读写，界面通过明确的业务命令访问。
- P0 仅允许一个实例写当前库；后台任务共享统一的数据访问层。

### 6.2 主要表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `library_meta` | library_id、schema_version、created_at | 文件库标识与结构版本 |
| `files` | id、current_path、path_key、display_name、name_search、extension、media_kind、size_bytes、modified_at、added_at、updated_at、availability、last_checked_at、last_error_code、volume_key、platform_file_id、content_revision、is_favorite、record_version、removed_at | 文件引用、属性、可用性与并发版本 |
| `file_notes` | file_id、body、body_search、updated_at、record_version | 文件级备注，一文件最多一条 |
| `tags` | id、name、name_key、created_at、updated_at、last_used_at、record_version | 标签实体 |
| `file_tags` | file_id、tag_id、created_at | 多对多关联，联合主键 |
| `preview_cache` | file_id、content_revision、variant、renderer_version、cache_path、status、last_error_code、updated_at | 预览缓存索引，内容可以重建 |
| `app_settings` | key、value_text、updated_at | 外观与基础偏好；复杂配置使用有版本的结构 |
| `schema_migrations` | version、applied_at | 已执行的数据库迁移记录 |

会话撤销队列和扫描任务状态可在内存中维护。恢复切换状态必须独立持久化；不能仅放在即将被替换的数据库里。

P1 智能集合新增集合实体与查询条件存储。查询结构带独立版本，标签条件保存标签 ID，标签重命名不应使集合失效。

### 6.3 约束与索引

- `files.id`、`tags.id` 使用不依赖路径的唯一标识。
- `files.path_key` 唯一；软移除后再次加入优先恢复原记录。
- `file_tags(file_id, tag_id)` 唯一，并为 `tag_id, file_id` 建反向索引。
- `tags.name_key` 唯一。使用应用层明确的 Unicode 规范化规则，不假设数据库默认排序规则满足所有语言要求。
- 文件名、修改时间、加入时间、收藏状态和移除状态按实际查询计划建立索引。
- 每个数据库连接显式启用并验证外键；引用不存在的文件或标签应失败。依据：[SQLite 外键支持](https://www.sqlite.org/foreignkeys.html)。
- 标签全局删除使用受控事务；撤销需要保留原标签实体及其关联快照。
- 时间在存储层使用 UTC；界面转换为用户时区。
- 路径比较遵循实际文件系统语义。保留路径原始大小写，不简单将所有 Windows 路径强制转小写来判重。

### 6.4 搜索实现边界

首版允许对目标规模内的规范化元数据执行参数化子串查询，先验证行为正确性，再按实测瓶颈引入专用索引。

普通索引不能被假定为任意子串查询带来加速。超过性能预算时，应分析查询计划并评估中文检索方案，不能通过取消备注搜索或改变匹配语义悄悄达标。

标签组合优先通过关联表的交集、存在性或分组计数实现。统计标签使用量时只计算未移除文件，防止列表与计数口径不一致。

### 6.5 持久化与迁移

- 模式变更必须带迁移脚本与版本号，不在运行时零散补列。
- 迁移前创建一致性备份，迁移失败保留旧库并报告。
- 自动保存与批量标注有清晰的提交边界，不能只更新前端缓存后显示已保存。
- 数据库不可写时，保留未保存备注草稿；标签界面恢复到最后已提交状态。
- 重建缓存不触碰标签、备注和文件关联。

## 7. 建议技术方案

### 7.1 建议选型及验证要求

| 层次 | 建议方案 | 本项目中的职责 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | 窗口、应用生命周期、系统文件选择与本地能力边界 |
| 界面 | React + TypeScript | 文件视图、筛选、标签编辑、详情和设置 |
| 本地服务 | Rust | 文件访问、扫描、业务校验、任务调度、数据库操作 |
| 元数据库 | SQLite | 文件记录、标签、备注与查询 |
| 缩略图 | 本地图片解码与 PDF 渲染适配层 | 解码、尺寸限制、任务取消与缓存 |
| 测试 | 核心业务单元测试、数据库集成测试、桌面流程验证 | 数据正确性和用户流程 |

这是一套建议组合。Tauri 允许用 Web 前端配合本地后端构建桌面应用，适合用来验证本方案的界面与本地能力分层；这不代表它已经解决本项目所有预览和文件跟踪问题。依据：[Tauri 官方概览](https://v2.tauri.app/start/)。

正式开发前固定依赖版本并提交锁文件，不在本规格中将某个补丁版本写为“最新版”。PDF 渲染器、图片解码库和数据库访问库在技术验证中选定，并记录许可证与打包结果。

如果团队不具备 Rust 开发条件，应在技术验证阶段评估其他桌面方案；产品行为和数据约束保持一致，不同时维护两套首版实现。

### 7.2 模块边界

```text
界面层
  导航 / 文件网格 / 文件列表 / 搜索条件 / 详情 / 设置
                       ↓ 业务命令与事件
应用服务层
  导入 / 标签 / 搜索 / 备注 / 预览 / 文件操作 / 备份恢复
                       ↓
基础设施层
  SQLite / 文件系统适配 / 系统打开接口 / 解码器 / 缓存
```

建议代码按业务领域组织：`library`、`tags`、`search`、`notes`、`preview`、`backup`、`settings`。前端组件不直接访问数据库或拼接系统命令。

### 7.3 文件访问边界

用户主动选择或拖入的文件和目录由本地服务登记。预览和打开通过文件 ID 查找已登记记录，校验真实路径及当前状态。前端提供的任意字符串不能自动获得全盘文件访问能力。

使用 Tauri 能力配置限制窗口与插件权限；自定义本地命令仍需自行检查输入和路径，不能将能力配置当作本地代码校验的替代。依据：[Tauri Capabilities](https://v2.tauri.app/security/capabilities/)。

预览中的文件内容按不可信数据处理：备注按纯文本显示，HTML/SVG 不直接执行，PDF 脚本与远程内容不得获得应用权限。P0 运行时资源随包提供，核心功能不依赖网络 CDN。

### 7.4 后台任务

扫描、文件检查、缩略图和备份任务均不得阻塞界面线程。任务有唯一 ID、进度、终态和取消信号。

扫描队列与缩略图队列分别限制并发。预览优先处理当前选中与可见项目，滚动离开的任务可降级优先级。失败任务限制重试次数，避免对同一个损坏文件无限重试。

读取文件前后发现修改时间、大小或身份变化时，丢弃不一致的预览产物并重新排队。单个任务失败不影响用户编辑已有标签。

## 8. 业务命令与查询契约

本节描述应用内部接口，使用参数与结果表表达，不绑定具体传输编码。

### 8.1 核心命令

| 命令 | 输入 | 输出 | 关键约束 |
| --- | --- | --- | --- |
| `library.import` | 已选路径、是否递归、扫描选项 | 任务 ID | 逐项提交，允许取消，重复加入幂等 |
| `library.cancelImport` | 任务 ID | 当前任务终态或取消请求确认 | 保留已提交记录 |
| `files.query` | 查询规格、分页游标、请求序号 | 记录列表、总数、下一游标、请求序号 | 统一匹配语义 |
| `files.get` | 文件 ID | 文件属性、标签、备注、预览状态、版本 | 不因原文件暂不可用而丢失标注 |
| `tags.create` | 名称 | 标签实体 | 规范化后唯一 |
| `tags.rename` | 标签 ID、新名称、预期版本 | 新实体、撤销令牌 | 不覆盖同名标签 |
| `tags.delete` | 标签 ID、预期版本 | 影响数量、撤销令牌 | 事务删除实体与关联 |
| `files.patchTags` | 文件 ID 集合、添加标签 ID、移除标签 ID、预期版本集合 | 更新版本、变化数量、撤销令牌 | 同一标签不可同时添加和移除 |
| `notes.save` | 文件 ID、文本、预期版本 | 已保存版本、保存时间 | 过期请求返回冲突 |
| `files.setFavorite` | 文件 ID 集合、目标状态、预期版本 | 更新版本、撤销令牌 | 重复设置同值幂等 |
| `files.remove` | 文件 ID 集合、预期版本 | 影响数量、撤销令牌 | 只软移除记录 |
| `files.relink` | 文件 ID、新位置、确认结果、预期版本 | 更新文件记录、撤销令牌 | 不覆盖已占用位置 |
| `files.open` / `files.reveal` | 文件 ID | 成功或可解释错误 | 本地服务解析路径 |
| `files.copyPath` | 文件 ID | 成功或可解释错误 | 不通过 shell 拼接 |
| `files.refresh` | 文件 ID 集合或当前库 | 检查任务 ID | 不推断任意位置的移动 |
| `preview.request` | 文件 ID、目标尺寸、内容版本 | 缓存引用或任务 ID | 拒绝过期版本缓存 |
| `history.undo` | 撤销令牌 | 恢复结果、新版本 | 校验后续变更，事务执行 |
| `backup.export` | 用户选择的目标位置 | 任务 ID、最终文件位置 | 临时写入、校验后完成 |
| `backup.inspect` | 用户选择的备份 | 格式版本、日期、记录统计、可恢复状态 | 只读检查，不替换数据库 |
| `backup.restore` | 已检查备份、确认结果 | 任务状态 | 先备份、可回滚替换 |

### 8.2 查询规格

| 字段 | 说明 |
| --- | --- |
| scope | 全部、待整理、收藏、最近加入或不可用 |
| text | 原始搜索文本，按第 5.5 节解释 |
| include_tag_ids | 需要包含的标签 ID 集合 |
| include_mode | 全部匹配或任一匹配 |
| exclude_tag_ids | 需要排除的标签 ID 集合 |
| media_kinds | 类型分类集合，空集合表示不限 |
| modified_from / modified_to | UTC 起始闭区间与结束开区间 |
| directory / include_descendants | 可选目录范围及是否包含子目录 |
| availability | 可选可用性集合，空集合表示不限 |
| sort_field / sort_direction | 允许的排序字段与方向 |
| page_size / cursor | 分页大小与游标，服务端限制最大页大小 |
| request_seq | 前端用于丢弃过期响应的请求序号 |

### 8.3 错误契约

错误至少包含：稳定错误码、可读消息、是否可重试、相关记录或任务 ID。原始系统错误可以进入本地诊断记录，界面显示面向用户的描述。

主要错误码：`FILE_MISSING`、`LOCATION_OFFLINE`、`ACCESS_DENIED`、`TAG_NAME_CONFLICT`、`VERSION_CONFLICT`、`DATABASE_UNWRITABLE`、`PREVIEW_UNSUPPORTED`、`PREVIEW_TOO_LARGE`、`BACKUP_INVALID`、`BACKUP_VERSION_UNSUPPORTED`、`RESTORE_FAILED`、`PATH_ALREADY_LINKED`。

日志默认不记录备注正文或文件内容。诊断导出由用户主动触发，路径等信息可脱敏。

## 9. 智能集合与后续扩展约束

### 9.1 P1：智能集合

“保存当前筛选”为一个具名集合。集合只保存查询条件与视图偏好，不保存静态文件副本。

修改集合中的临时筛选不会自动覆盖原集合；显示“条件已修改”，用户选择更新集合或另存集合。

引用标签被删除时，集合标记条件失效，不静默扩大结果范围。引用标签重命名时根据 ID 自动展示新名称。

### 9.2 P1：目录监听

监听是用户显式开启的持久设置，不能因一次加入文件夹就默认永久监听。支持暂停与移除监听，不连带移除已加入文件。

事件可能重复、丢失或乱序，必须去重并提供重新扫描校准。监听只负责发现变化，最终文件身份与数据库更新通过统一服务处理。

### 9.3 P2：局部标注

局部标注独立存储类型、文件 ID、内容版本、页码、归一化坐标和备注。原文件内容变化后标记为“需要复核”，不能假设旧坐标仍然准确。

### 9.4 P2：识别与 AI

机器建议标签与用户确认标签分开保存，用户可以接受、拒绝或编辑。OCR、向量与模型结果都属于可重建索引，不替代人工标注。

增加云端服务时另行定义上传范围、开关、失败降级和费用提示；不得把本地文件默认上传作为首版的隐含行为。

## 10. 性能、可靠性与可用性目标

以下是建议验收预算，不是已经实测的性能声明。技术验证阶段允许据真实硬件调整，但必须记录原因与替代目标。

基准环境建议：Windows 11 x64、16 GB 内存、本地 SSD；10,000 条文件记录、500 个标签、平均每文件 5 个标签，备注平均约 1 KiB。记录 CPU、磁盘与应用构建版本，使用发布构建测量。

| 项目 | 初始目标 | 测量边界 |
| --- | --- | --- |
| 启动可交互 | 3 秒以内 | 不等待全库扫描与缩略图完成 |
| 搜索服务响应 | 热缓存 p95 ≤ 300 ms | 包含文本与标签组合，至少 100 组有代表性的查询 |
| 输入到结果更新 | 通常 ≤ 600 ms | 含输入防抖；输入法组合过程不计作完整查询 |
| 已缓存预览切换 | p95 ≤ 200 ms | 常见图片与目标显示尺寸 |
| 100 个文件批量标签修改 | p95 ≤ 500 ms | 本地数据库提交与结果反馈 |
| 长列表滚动 | 不因全量挂载出现持续卡顿 | 采用虚拟化，后台解码不占用界面线程 |
| 单文件异常 | 不导致应用崩溃或整批中断 | 覆盖损坏、无权限、巨大图片与离线位置 |

达到容量目标依赖数据分布，不能只用空备注和单标签数据证明性能。冷启动、热查询与后台扫描同时发生的情况分别记录。

无障碍要求：主要操作可以通过键盘完成；控件具备可读名称；状态变化有适当提示；文本对比度满足常用无障碍目标；不要求用户仅靠颜色判断状态。

## 11. 验收用例

### 11.1 功能与数据正确性

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| A01 | 加入单文件与递归文件夹 | 产生正确记录；原文件路径、内容与修改时间不因标注而变化 |
| A02 | 重复加入相同路径 | 不产生第二条记录，既有标签和备注完整保留 |
| A03 | 加入不同目录下相同内容文件 | 保留独立记录，能通过父目录区分 |
| A04 | 同名标签与规范化冲突 | 空名称被拒绝；规范化后的重名不产生重复标签 |
| A05 | 同一文件多个标签 | 添加、移除、重启后读取都正确；重复添加无重复关系 |
| A06 | 批量标签混合状态 | 正确显示部分拥有；批量添加后撤销只恢复实际变化 |
| A07 | 批量修改中途失败 | 整个元数据事务回滚，界面不残留假成功状态 |
| A08 | 备注保存与文件切换 | 输入、切换、重启后内容正确，不串写到其他文件 |
| A09 | 自动保存失败 | 显示失败，保留草稿，重试后状态恢复 |
| A10 | 全部、任一与排除标签 | 使用同一组固定样本，精确匹配第 5.5 节语义 |
| A11 | 中文与特殊字符搜索 | 中文子串有效；百分号、下划线等不成为查询通配符 |
| A12 | 连续快速搜索 | 旧查询晚返回时不覆盖新结果，输入焦点和光标保持 |
| A13 | 待整理与收藏 | 范围准确；待整理文件首次加标签后离开结果 |
| A14 | 图片、PDF 与 Office 文件 | 图片和 PDF 首页可预览；Office 按规格降级且可外部打开 |
| A15 | 损坏或过大文件 | 应用保持可用，显示具体预览失败原因 |
| A16 | 原文件修改 | 可见预览刷新后不继续使用过期缓存 |
| A17 | 文件不存在与磁盘离线 | 保留标签和备注；可判断时区分缺失与离线 |
| A18 | 手动重新关联 | 内部 ID、标签、备注和收藏不变；预览重新生成 |
| A19 | 重新关联到已占用路径 | 不覆盖或吞并另一条记录 |
| A20 | 从库移除并撤销 | 原文件始终存在；撤销恢复记录和标注 |
| A21 | 移除后重新加入 | 恢复原记录和标注；身份变化时不静默关联 |
| A22 | 标签重命名与删除 | 关联文件同步更新，撤销可恢复实体与关联 |
| A23 | 导出并恢复备份 | 标签、关联、备注、收藏及稳定 ID 一致 |
| A24 | 损坏或不支持版本的备份 | 在替换当前库前拒绝，当前库保持完整 |
| A25 | 恢复时进程中断 | 下次启动可回到完整旧库或完整新库，不丢失两份数据 |
| A26 | 数据库升级失败 | 保留旧库与备份，不在部分迁移状态继续写入 |
| A27 | 清理缓存 | 标签、备注及文件关联不变，缩略图可以重建 |
| A28 | 断网使用 | P0 的加入、标注、搜索、预览和备份均不要求联网 |

### 11.2 交互验收

- 三档窗口大小与三档系统缩放下，主要操作和状态信息无遮挡。
- 网格与列表切换后，筛选条件和选择保持一致。
- 输入框中 Ctrl+A、Ctrl+Z、空格和 Enter 不触发错误的文件区操作。
- 标签创建支持中文输入法，不把尚在组合中的词提交。
- 多选时展示数量，批量修改范围清楚。
- 文件与标签为空、无搜索结果、扫描中、预览失败、保存失败分别有对应状态。
- 主要动作无需鼠标悬停才能发现。
- 关闭窗口前未保存备注得到处理，不静默丢失。

### 11.3 测试分层

单元测试覆盖标签规范化、搜索逻辑、撤销差异和状态转换。数据库集成测试覆盖事务回滚、约束、迁移、备份与恢复。端到端验证覆盖加入到打开的完整流程，以及文件系统异常。

测试文件使用专用临时样本，不对用户真实目录执行删除、改名或故障注入。测试至少包含中文路径、空格、同名文件、大小写差异、深层目录与不可访问位置。
