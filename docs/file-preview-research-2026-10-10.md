# 拾签常见文件预览研究

日期：2026-10-10。结论：可以在保持轻量安装包的前提下，补齐常见文件的内容预览；完整还原办公软件的排版应作为可选能力。本文是方案研究，未在本轮安装 Word/Excel 预览依赖或启用对应功能。

## 当前实现与体积基线

代码入口为 `src/preview.tsx`、`src-tauri/src/fsops.rs`。图片使用本地缩略图；PDF 已内置 PDF.js 6.3.289，动态加载解析库，并在 Worker 中渲染第一张页面；文本的大预览读取前 200 KiB；Office 文件目前显示类型图标。

PDF 卡片最长边 420 px，放大预览最长边 1800 px，两者均仅第一页。后端限制 PDF 为 30 MiB。已有 3 个预览并发槽、内存结果缓存和按文件版本区分的磁盘图片缓存；后续能力应接入同一链路，而非让每张卡片初始化完整阅读器。

现有 AI 标注模块能从 DOCX、XLSX、PPTX 的 XML 提取部分文本，但这是供分类使用的文本，不包含准确分页、Excel 单元格位置和完整样式。不能直接等同于用户可用的 Office 预览。

Beta.10 基线安装器 5,970,591 字节，EXE 14,569,472 字节（约 5.69 MiB / 13.89 MiB）。PDF 生产脚本约 421 KiB，Worker 约 1.21 MiB；CMap、标准字体和 WASM 合计约 3.35 MiB。已经在安装包内，无需再引入一套 PDF 引擎。

## 建议支持层级

| 文件 | 卡片 | 放大预览 | 推荐优先级与边界 |
| --- | --- | --- | --- |
| PDF | 第一页图片，附总页数 | 翻页、缩放、按需渲染；文字选取后续增加 | 第一优先级，复用 PDF.js |
| DOCX | 内嵌缩略图（存在时），否则标题和首段 | 本地 HTML 文档阅读器 | 第二优先级，复杂分页可能不一致 |
| XLSX / CSV | 第一工作表前几行的清晰表格 | 工作表切换、冻结表头、虚拟滚动 | 第二优先级，展示已保存的单元格值 |
| XLS | 轻量解析器支持时加入 | 工作表内容预览 | 验证兼容性后开放 |
| DOC / PPT | 系统缩略图（若可用），否则类型卡片 | 默认程序打开，或可选转换器 | 基础包不承诺完整内置渲染 |
| PPTX | 内嵌缩略图（存在时） | 初期仅文本/图片摘要 | 高保真幻灯片另立可选方案 |

卡片应以“快速辨认文件”为目的，避免把整份 Word 或工作簿塞进瀑布流。预览保持只读，不改写原文件。

## 方案对比

### A. 轻量本地预览（推荐）

PDF 使用既有 PDF.js。DOCX 可用 docx-preview + JSZip 渲染 HTML；库官方说明其排版受 HTML 能力限制，也不适合高效生成缩略图，所以卡片优先提取 OOXML 内嵌缩略图或生成首段摘要，仅放大阅读时加载完整渲染器。[docxjs 官方说明](https://github.com/VolodymyrBaydalka/docxjs)

Excel 可选择 SheetJS 进行格式解析，再由拾签的虚拟表格显示内容；也可单独评估 Rust 解析器，减少前端传输完整文件的成本。SheetJS 解析公式与结果是不同能力，社区解析库不会自动计算公式。优先显示文件里保存的结果，无结果时显示公式并说明。[解析选项](https://docs.sheetjs.com/docs/api/parse-options/) · [公式说明](https://docs.sheetjs.com/docs/csf/features/formulae/)

DOCX + JSZip 的两份 min.js 实测合计 173,308 字节（169.25 KiB），分别 gzip 后合计 49,108 字节（47.96 KiB）。测量版本为 docx-preview 0.4.1、JSZip 3.10.2，取自 npm registry tarball。它们的完整解包尺寸合计约 1.59 MiB，包含源码等，不应全部打包。数据见 `docs/evidence/preview-library-sizes-2026-10-10.csv`。

这些数值是库资产测量，不是最终安装器的增量；Tauri 嵌入与 NSIS 压缩之后仍需做有无依赖的双构建对比。SheetJS 官方 CDN 在本次下载返回 HTTP 403，未获得可核验的当前库体积，不拿旧版或第三方镜像数值冒充当前实测。

建议第一期为 Word/Excel 预览设置“安装器增量不超过 2 MiB”的目标预算；这是验收目标，不是已经实现的体积承诺。动态 import 减少启动成本，但不会减少总安装包大小。

### B. Windows 系统预览/缩略图（可选增强）

通过系统缩略图接口取图，或在专用原生宿主嵌入 Preview Handler。拾签不需要携带整个办公引擎，但结果取决于电脑安装的处理器、格式和系统配置；不能保证同事的电脑一定可用。缩略图与可交互预览是两种接口，应独立设计和验证。[缩略图接口](https://learn.microsoft.com/en-us/windows/win32/api/thumbcache/nn-thumbcache-ithumbnailcache) · [Preview Handler](https://learn.microsoft.com/en-us/windows/win32/shell/preview-handlers)

Tauri 的 HTML 容器不能直接容纳任意 COM 预览处理器；需要 HWND 宿主、尺寸同步、焦点处理、崩溃隔离。适合后续 Windows 专属增强，不作为第一期唯一途径。

### C. 完整 Office 转换引擎（基础包暂不采用）

可调用用户已经安装的 LibreOffice，将文档转换为 PDF，再复用 PDF 预览；官方提供 headless 和 convert-to 参数。[LibreOffice 参数说明](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html)

如果在安装包携带完整引擎和字体资源，体积及更新维护成本会明显高于本项目当前约 6 MB 的安装器。未下载引擎做 A/B 实测，因此不报精确增量。转换器应独立安装、按需启用，有超时、取消、独立用户配置目录和临时文件清理。转换后的格式也不保证与 Microsoft Office 完全一致。

在线 Office 查看器需要联网并让服务访问文档，与默认本地资料库体验不符，不纳入默认预览。

## 性能与安全设计

- 后端用已导入文件 ID 授权访问，校验身份与版本；避免前端任意路径读取。文件变动后使缩略图失效。
- OOXML 提取内嵌缩略图应校验 ZIP 条目和图片尺寸；文档解析限制压缩包条目数、解压总量、单项大小和处理时间。已有 AI 文本提取的限额不能自动代表新渲染器受控。
- Word 渲染在独立受限容器中，不接收外链、宏或任意 HTML；关闭 altChunk 等不需要的能力，验证嵌入字体、图片及超链接。当前 CSP 的 frame-src 为 none，若引入 iframe 隔离需明确调整策略并回归。
- Excel 使用 Worker 或后台线程解析；只渲染当前视口。SheetJS 官方也建议浏览器大文件解析使用 Worker。[大数据文档](https://docs.sheetjs.com/docs/demos/bigdata/stream/)
- 文件大小限额只是第一道门槛，大压缩比、巨量单元格与高分辨率图片仍需独立限制。异常时回退类型卡片，保留“用默认程序打开”。
- 缩略图磁盘缓存应增加容量上限与清理；当前 300 项内存限制不等于磁盘缓存受限。分页阅读不长期保留所有页面 Canvas。
- 图片/PDF 的 3 个并发槽不适合直接扩展为 3 个重型 Office 渲染任务：Office 初期独立并发 1，滚出视口的任务可取消，优先当前选中文件。

## 实施顺序与验收

1. PDF 阅读器：分页/页数/缩放复用现有依赖；先验证中文字体、扫描件、图片压缩、损坏/加密文件与连续切换内存释放。不要为相同第一页重复传输整个 PDF。
2. DOCX/XLSX 卡片：内嵌缩略图优先；缺失时使用首段或表格摘要。验证摘要的结构和中文可读性。
3. DOCX 只读阅读与 Excel 工作表阅读：按需加载、复杂样式降级、巨量行列虚拟化，明确公式展示边界。
4. 实测有无依赖的 EXE/安装器差值，并记录首次打开耗时、峰值内存及缓存磁盘增长。初期目标：普通 1–5 MiB 文件冷预览 2 秒内、缓存卡片 100 ms 内；测试机器与样本必须固定。这些是建议目标，尚未测得。
5. 仅当用户确有高保真旧格式需求，再加入 Windows 系统处理器或独立转换器。

推荐决策：基础包内置 PDF + DOCX + XLSX 内容预览；高保真旧格式走可选增强。当前轮只修复分隔条并完成研究，不修改预览功能边界。
