# 拾签 v0.2.0 · 标签浮窗开发与使用说明

更新日期：2026-10-02。适用平台：Windows 11 x64。

## 本次实现

在已有本地标签资料库上增加独立、置顶的标签浮窗。用户可以预先准备常用标签，在整理图片或其他本地文件时直接拖动标签完成标注。

标注存入拾签的 SQLite 资料库，原文件的位置与内容保持不变。一个文件可以叠加多枚标签，也可以通过这些标签在工作台中查找。

## 开始使用

1. 打开工作台，在左下角点击「标签浮窗」。
2. 浮窗首次打开时内置「灵感」「参考素材」「待处理」「已完成」。
3. 按住一枚标签，拖到桌面、Windows 资源管理器中的具体文件或拾签内文件卡片上，松手完成标注。未加入拾签的外部文件会自动入库。
4. 再拖另一枚标签到同一文件，可以继续叠加标签。重复添加同一标签会提示已经存在，不会产生重复记录。
5. 从工作台左栏选择标签，即可找到刚才标注的文件。

也支持反向操作：在资源管理器选择一个或多个文件，拖到浮窗中的某一枚标签上。放下前该标签会高亮，放下后显示结果。

不便拖拽时，点击选中一枚标签，再点击「选择文件标注」，通过系统文件选择器添加一个或多个文件。

## 自行预制标签

点击浮窗右上角的预设管理按钮：

- 在输入框输入名称，点击加号或按 Enter，创建并固定标签。
- 勾选文件库已有标签，将它加入浮窗。
- 取消勾选，只会从浮窗移除这枚预设，文件已有标注会保留。
- 最多固定 24 枚标签。较多标签时可在标签区滚动。
- 标签名称沿用资料库校验规则：1～40 个可见字符，不允许换行与控制字符；同名标签复用已有记录。
- 在主窗口重命名或删除标签后，浮窗会同步更新。
- 预设持久化到数据库，重启后保留，并随 `.sqtagbackup` 备份恢复。

首次内置标签只初始化一次。用户清空预设后不会自动重新塞入默认标签。

## 浮窗交互

| 操作 | 结果 |
| --- | --- |
| 拖动顶部「拾签」标题区域 | 调整浮窗位置 |
| 点击收起箭头 | 收成 340 × 64 的小条 |
| 点击展开箭头 | 恢复 340 × 460 的标签面板 |
| 点击打开工作台 | 显示并聚焦主窗口 |
| 主窗口关闭且浮窗仍显示 | 保存备注后隐藏主窗口，浮窗继续可用 |
| 点击关闭浮窗 | 隐藏浮窗；如果主窗口隐藏，会恢复主窗口 |
| 浮窗未显示时关闭主窗口 | 保存备注后退出程序 |
| 拖标签过程中按 Escape | 取消本次拖动 |
| 点击底部撤销按钮 | 撤销资料库的上一步可撤销操作，提示中显示操作名称 |

浮窗跟随主窗口的浅色／深色／跟随系统主题设置。拖拽目标为拾签内文件时，文件卡片高亮；标注成功或失败会在浮窗底部反馈。

撤销标注只移除本次新增加的标签关联，其他标签、备注和原文件保留；自动加入的文件记录仍保留在资料库。

## 范围和边界

| 场景 | 行为 |
| --- | --- |
| 桌面、Windows 资源管理器中的真实文件 | 通过 Windows Shell 与 UI Automation 获取文件路径并标注 |
| 拾签文件网格与列表 | 对命中的单个文件添加标签 |
| 多个文件拖入同一标签 | 整批标注，最多 1,000 个文件 |
| 文件夹、空白处、系统虚拟项 | 拒绝标注并提示选择具体文件 |
| 多个同名 Shell 项无法唯一确定路径 | 拒绝猜测，可改用文件拖入或文件选择器 |
| 第三方文件管理器、浏览器网页内图片 | 暂不支持向这些界面拖标签；可把保存后的本地文件拖入浮窗 |
| 原位置已换成另一个文件 | 保留旧标注并要求重新关联，不自动继承 |
| 批次中存在无效路径或应用资料库文件 | 整批取消写入并显示原因 |

这次实现的是文件级标签标注；图片上的画框、涂画、箭头与区域文字不是本次功能。

## 开发结构

技术栈沿用 Tauri 2、React、TypeScript、Rust 和 SQLite。无需新建账号或外部服务。

| 文件 | 职责 |
| --- | --- |
| `src/Floating.tsx`、`src/floating.css` | 浮窗 UI、预设管理、原生文件拖入的命中、主题同步与反馈 |
| `src/App.tsx` | 浮窗入口、工作台文件命中、跨窗口数据刷新与关闭处理 |
| `src-tauri/src/floating.rs` | 创建置顶窗口、折叠展开、原生鼠标状态、取消和结果通知 |
| `src-tauri/src/shell_target.rs` | 校验可见 Shell 视图，解析鼠标下的 UIA 文件项，取得唯一文件系统路径 |
| `src-tauri/src/annotation.rs` | 内置预设初始化、持久化、自动入库、事务标注及撤销记录 |

### 数据与一致性

预设使用已有 `settings` 表的 `floatingTags` 键，内容为有序标签 ID 数组。未增加数据库表，继续使用原有数据库版本。

批量标注先检查输入和文件元数据，再用 SQLite SAVEPOINT 包住文件记录与关联写入；失败回滚整批。关联表的复合主键保证同一文件不会重复拥有同一标签。文件版本与备注版本保持独立。

成功的标签创建、重命名、删除、标注和设置修改发出 `library-changed`，主窗口和浮窗重新读取状态。拖拽相关事件负责命中高亮与最终反馈。

### Windows 拖拽实现

从浮窗标签按下并移动超过 5 个界面像素后，进入本次标签拖动会话。后端仅在会话期间读取鼠标状态，释放后解析目标。Escape、关闭浮窗或超时会结束会话，没有常驻的全局鼠标钩子。

工作台命中采用物理屏幕坐标换算到窗口内逻辑坐标；外部文件通过可见 Shell 视图和 UI Automation 定位，不拼接或猜测文件夹路径，也不会发起文件复制或移动。

接口依据：[Microsoft UI Automation：ElementFromPoint](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomation-elementfrompoint)、[Microsoft：通过 Shell 视图访问桌面项目](https://devblogs.microsoft.com/oldnewthing/20130318-00/?p=4933)。

## 升级与运行

关闭正在运行的旧版拾签，再运行 v0.2.0 安装包或直接启动新 EXE。新版本使用相同的正式应用标识和资料库位置，继续读取原有文件、标签、备注和收藏。可以先在偏好设置中导出标注备份。

EXE 单文件运行仍依赖系统 WebView2；资料库保存在用户应用数据目录，不保存在 EXE 旁边。标注备份不包含原文件。

构建命令：

```powershell
npm ci
npm run desktop
npm run test:core
npm run package
```

详细验证结果、测试工具限制和未覆盖场景见 `validation-v0.2.md`。
