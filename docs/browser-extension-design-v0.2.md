# 拾签：桌面端与浏览器扩展协同开发文档

## 1. 产品定位与协同价值

### 1.1 一句话定位

**浏览器负责在发现资料时及时采集和标注，桌面端负责统一整理、检索、预览与使用。**

用户在网页上遇到参考图、文章、链接或一段有用的文字时，直接加上与桌面端一致的标签。之后无论资料最初来自网页还是本地目录，都可以按同一项目和用途找到。

### 1.2 典型使用场景

| 场景 | 浏览器侧行为 | 桌面侧结果 |
| --- | --- | --- |
| 发现设计参考图 | 右键图片，选择标签并保存图片到本地 | 本地图片副本、来源页面和标签一起进入资料库 |
| 收藏一篇文章 | 点击扩展，保存标题、链接、备注 | 形成网页资料，不伪装成已下载的文件 |
| 摘录一段说明 | 选中文字，右键保存摘录 | 保留文本、来源与可用的定位提示 |
| 同项目收集多种资料 | 给网页、图片和本地需求文档使用相同标签 | 桌面端按项目混合检索 |
| 工作中需要旧资料 | 在扩展中按关键词和标签搜索 | 找到网页或本地文件，在对应环境打开 |
| 桌面窗口已关闭 | 扩展连接允许唤起的后台服务，或暂存任务 | 不要求始终打开桌面主窗口 |
| 页面或图片链接失效 | 查看已保留的来源、摘录和下载副本 | 能区分仍可用内容与仅剩来源的记录 |

### 1.3 产品边界

- 扩展优先处理用户主动选择的当前网页内容，不自动收集浏览历史。
- 本地已有文件继续保留原位置；用户主动保存的网页图片进入专门的本地采集目录。
- 网页收藏默认保存标题、URL 和标注，不承诺整页离线阅读。
- 浏览器与桌面端共享一套标签身份和检索语义。
- P0 不引入账号、云同步或多人协作。
- P0 不做全站抓取、后台批量下载、付费内容解锁或登录凭据转移。

### 1.4 本次方案的假设

“同时开发”在本文中指桌面端与浏览器扩展作为同一产品计划推进。建议先确定共享模型和通信契约，再让两端分别实现，避免桌面端定型后重新改造数据结构。

本文 P0 指“浏览器协同首版”的范围。原桌面端的必要功能仍按 v0.1 执行，冲突处以本文件第 2 节的明确修订为准。未列为修订的原规则继续有效。

## 2. 对桌面端原规格的必要修订

浏览器扩展会带来新的资料类型、本地保存副本和第二个操作入口，需要同时调整桌面端。

| 原规格 | 协同版本修订 | 原因 |
| --- | --- | --- |
| 文件是标签与备注的唯一归属对象 | 引入统一“资料”实体，支持本地文件、网页、网页图片与文字摘录 | 链接没有本地路径，不能强行建成文件记录 |
| 全部文件为主要入口 | 增加“全部资料”，保留“本地文件”筛选与入口 | 同一标签可以跨类型查找 |
| 原文件只引用，不复制 | 本地导入继续只引用；网页图片经用户主动保存后产生受管理副本 | 两种来源的存储责任不同 |
| 备份只含元数据 | 新版完整备份默认包含受管理的网页图片原始副本 | 这些副本可能是用户唯一保留的内容 |
| 桌面应用内部服务访问数据库 | 抽出单实例本地资料服务，桌面界面与扩展都经它读写 | 统一事务、版本、标签身份和备份锁 |
| 搜索文件名、标签、备注 | 按资料类型搜索标题、标签、备注、来源域名与摘录文本 | 仍不自动索引整页正文 |
| 只有本地文件可用性 | 本地文件、网页链接、下载副本分别维护状态 | 链接没有离线副本并不等于文件缺失 |
| 标签使用量统计文件数 | 统计资料数；当前视图显示该范围内的资料数量 | 避免同一图片及其副本重复计数 |

共同保留：多标签、组合筛选、批量标注、事务写入、撤销、纯文本备注、稳定 ID、原文件不被意外修改等要求。

旧桌面客户端不得直接打开升级后的数据库继续写入。若已有 v0.1 数据库，按第 10 节迁移；若尚未开发，则直接采用统一资料模型。

## 3. 资料类型与存储模式

### 3.1 统一资料类型

| 类型 | 核心内容 | 本地持久内容 | 默认打开方式 |
| --- | --- | --- | --- |
| 本地文件 `local_file` | 用户已有文件的引用 | 标签、备注、路径与属性 | 系统默认程序 |
| 网页 `web_page` | 网页标题和 URL | 链接、标签、备注、采集记录 | 浏览器打开链接 |
| 网页图片 `web_image` | 图片来源、所属页面，可选图片副本 | 来源与标注；保存成功时含图片字节 | 有副本则预览图片，否则打开来源 |
| 文字摘录 `web_excerpt` | 用户选中的文本及出处 | 摘录、标签、备注、定位提示 | 展示摘录，可打开来源 |

同一网页的书签、其中的图片和一段摘录是不同资料，拥有各自的标签和备注。它们可以通过来源关系关联，但不自动继承或同步标签。

### 3.2 用户必须能区分的保存结果

| 界面文案 | 实际保存内容 | 是否可离线使用内容 |
| --- | --- | --- |
| 已保存网页链接 | 标题、URL、标签、备注 | 可看标注；不能保证查看网页正文 |
| 已保存图片来源 | 来源页面、图片地址、标签、备注 | 不保证能看到原图 |
| 图片已保存到本地 | 完整图片字节、来源信息、标签、备注 | 可以查看已保存图片 |
| 摘录已保存 | 所选文本及来源 | 可以阅读摘录 |
| 已暂存，等待连接 | 仅保存在当前浏览器配置中的发送队列 | 不代表已经进入桌面资料库 |
| 图片尚未获取 | 保存意图存在，未取得完整字节 | 不能称为图片已离线保存 |

缩略图不能替代原始图片副本。缓存清理只能删除可重建缓存，不得删除受管理的原始采集文件。

### 3.3 同一标签跨来源使用

例如“品牌升级”下同时出现：本地需求 PDF、品牌官网链接、网页参考图和一段文章摘录。用户选择“参考图”后继续缩小范围，不需要考虑资料来源。

资料类型单独作为筛选维度。时间筛选新增明确的“加入时间”，适用于所有资料；原“文件修改时间”只在本地文件范围启用，不把网页采集时间冒充文件修改时间。

## 4. 浏览器扩展功能范围

### 4.1 P0：协同首版

| 编号 | 功能 | 主要交互 | 完成条件 |
| --- | --- | --- | --- |
| E01 | 保存当前网页 | 工具栏弹窗 | 保存标题、URL、标签与备注 |
| E02 | 保存链接目标 | 网页链接右键菜单 | 明确保存的是链接目标，并保留发现它的页面 |
| E03 | 保存图片来源 | 图片右键菜单 | 保存图片 URL 与来源页面 |
| E04 | 保存图片到本地 | 采集编辑页中的明确操作 | 支持公开 HTTPS JPEG、PNG、WebP，传输后校验入库 |
| E05 | 保存选中文字 | 选区右键菜单 | 保存纯文本、页面 URL 与有限定位提示 |
| E06 | 统一标签与备注 | 标签输入框、最近标签、纯文本备注 | 与桌面端遵守同一命名和保存规则 |
| E07 | 当前目标重复检测 | 打开采集界面时查询 | 提示已存在资料，提供补充操作 |
| E08 | 在浏览器搜索资料 | 弹窗搜索入口、扩展独立页 | 搜索桌面库，支持标签组合和类型筛选 |
| E09 | 在桌面端定位资料 | 搜索结果或保存完成页 | 打开桌面界面并选中指定资料 |
| E10 | 持久暂存队列 | 状态入口和队列管理页 | 断线可恢复，重试不重复入库 |
| E11 | 首次连接与诊断 | 引导页、连接状态 | 区分未安装、未配对、已断开、版本不兼容 |
| E12 | 配套桌面能力 | 统一模型、来源详情、托管图片、备份升级 | 所有资料统一查询和可靠保存 |

E04 是首版中最需技术验证的功能。它必须至少支持无登录要求、无特殊请求头、无重定向的公开 HTTPS 图片。不能将“所有网页图片均可下载”作为承诺。

### 4.2 P1：增强效率

- 原生浏览器侧栏，用于连续采集、持久搜索和资料详情。
- 当前网页图片列表与用户勾选后的批量采集，限制数量，不默认收集全页。
- 当前可见区域截图；网页局部截图需明确捕获范围。
- 显式选择的下载任务与本地文件关联。
- 阅读模式正文提取、智能集合、标签合并与分组。
- 摘录回到网页后的尽力定位与临时高亮。
- 导出尚未交付的扩展队列，降低浏览器迁移风险。

浏览器侧栏 API 的打开条件与版本能力需要适配，不能依赖后台任意时刻自动弹出。依据：[Chrome Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)。

### 4.3 P2：后续探索

- 网页快照与整页离线阅读，单独设计资源完整性和安全渲染。
- 持久网页高亮、局部图片标注与版本复核。
- OCR、AI 标签建议、语义检索与相似图片。
- Firefox / Safari 适配、跨设备同步与协作。

P0 不自动整理全浏览器书签、不监控所有下载、不读取密码或 Cookie，也不把扩展做成与桌面端平行的第二套资料库。

## 5. 界面与关键使用流程

### 5.1 界面分工

| 界面 | 职责 | 不应承担的内容 |
| --- | --- | --- |
| 工具栏弹窗 | 当前页快速收藏、简短标签备注、最近结果入口 | 长时间上传、全量队列管理 |
| 网页右键菜单 | 根据页面、链接、图片、选区发起对应动作 | 强迫用户在多层菜单内编辑大量标签 |
| 扩展独立页 | 图片确认、较长编辑、搜索、队列、连接设置 | 任意浏览器历史采集 |
| 桌面端 | 完整资料整理、批量修改、预览、备份恢复 | 浏览器登录会话管理 |
| 浏览器侧栏 | P1 的持续工作入口 | P0 不依赖其可用性 |

普通弹窗会因失焦而关闭，重要操作必须先把草稿或队列写入持久存储，不能由弹窗的存活时间决定采集是否成功。

### 5.2 工具栏弹窗草图

```text
┌──────────────────────────────────────┐
│ 拾签                        已连接   │
├──────────────────────────────────────┤
│ 当前网页标题                         │
│ 来源域名                  已收藏提示 │
│                                      │
│ 标签  [品牌升级] [参考] [+ 添加]      │
│ 备注  [记录这份资料的用途……]         │
│                                      │
│ [保存网页链接]                       │
│                                      │
│ 搜索已有资料    待交付 2    在桌面查看│
└──────────────────────────────────────┘
```

弹窗建议宽约 360～420 px，布局随浏览器限制调整。标题最多两行，完整 URL 放在详情或可展开区域。保留一个明确的主要动作，不能只用未解释的图标表达“保存到哪里”。

标签使用与桌面端相同的字体层次、间距、形状和选中反馈。系统连接信息放在顶部小状态区；失败时说明下一步，不使用持续闪烁或整页警告色。

### 5.3 保存网页

1. 用户点击工具栏扩展，取得当前目标标签页的 URL 和标题。
2. 固定目标标签页与页面实例，生成采集草稿；不在保存瞬间重新抓取另一个活动标签页。
3. 已连接时查询重复项和最新标签；未连接时展示缓存标签及其更新时间。
4. 用户添加标签、备注，点击“保存网页链接”。
5. 先持久化操作，再尝试交付；主按钮防重复点击。
6. 只有桌面服务提交成功后显示“已保存网页链接”；否则显示“已暂存，等待连接”。
7. 提供“在桌面查看”和继续浏览入口。

用户可编辑资料标题，但原始网页标题保留在来源记录中。没有标题时用域名或 URL 作为可编辑初始值。

### 5.4 保存右键目标

右键菜单采用“拾签”分组，按目标显示“保存此页面”“保存此链接”“保存此图片”“保存所选文字”。使用浏览器上下文菜单提供的目标信息，不把所有动作都解释为当前页收藏。依据：[Chrome Context Menus API](https://developer.chrome.com/docs/extensions/reference/api/contextMenus)。

图片与选区动作打开扩展自己的采集编辑页，以便确认内容。浏览器 API 无法自动打开弹窗时使用此独立页，不采用未经验证的自动弹窗方案。

### 5.5 图片采集

采集页显示来源页面、图片来源域名、格式和可用尺寸信息，并提供两个明确选择：

- 保存图片到本地：取得完整图片字节，再交付桌面服务。
- 仅保存图片来源：只保存地址、标签和备注。

下载失败、权限拒绝或资源不支持时，保留草稿，提供重试及“改为保存来源”。不得自动降级后仍显示“图片已保存到本地”。

为减少首版不确定性，公开图片获取由扩展后台进行；桌面服务接收经过限制的字节流，不按网页提供的任意 URL 自行请求网络，也不接收浏览器 Cookie。

### 5.6 保存摘录

用户主动选中的文字作为主要内容，默认保留文本与段落换行，不复制整页 HTML。摘录长度建议上限 20,000 个用户可见字符，超出时要求缩短或确认保存明确标出的截取范围。

在权限允许时保存选区附近有限的前后文及定位提示。跨域框架或动态页面无法取得定位信息时，仍可保存浏览器提供的选中文字，并显示“无法精确定位原文”。

P0 不在重新打开网页时自动注入永久高亮。摘录即使失去原网页，也应能在本地阅读。

### 5.7 搜索与调用

扩展搜索沿用桌面端“包含全部、包含任一、排除”规则，初始最多返回 20 条摘要，可分页加载。

- 网页结果：在浏览器打开来源。
- 本地文件结果：点击“在桌面查看”；可在明确点击后交由本地服务打开原文件。
- 网页图片：有本地副本时可在桌面预览，另有“打开来源”动作。
- 摘录：在扩展独立页阅读短内容，完整编辑进入桌面端。

未连接时可以显示本浏览器最近成功采集的有限缓存，但必须标为“离线最近记录”，不能把它展示为完整资料库搜索结果。

## 6. 浏览器能力、权限与失败边界

### 6.1 首版权限建议

| 权限或能力 | 用途 | 申请方式 |
| --- | --- | --- |
| `activeTab` | 用户主动操作时读取当前页基本信息与允许的页面内容 | 首版声明 |
| `scripting` | 在获授权的页面执行短时提取逻辑 | 首版声明，按操作注入 |
| `contextMenus` | 页面、链接、图片和选区菜单 | 首版声明 |
| `storage` | 偏好、有限标签缓存和连接信息 | 首版声明 |
| `nativeMessaging` | 与本地桥接程序交换消息 | 首版声明 |
| `alarms` | 为暂存队列安排有限的重试机会 | 首版声明，不能承诺精确定时 |
| HTTPS 站点访问 | 获取用户选中的跨域图片 | 可选主机权限，按所需来源单独请求 |
| `sidePanel` | 原生侧栏 | P1 增加并验证浏览器适配 |
| `downloads` | 与用户选择的下载任务关联 | P1 功能启用时评估申请 |

P0 不申请浏览历史、Cookie、调试器、剪贴板读取或所有站点的持久必需访问权。只读取用户主动触发操作的页面；全库搜索只在扩展界面中呈现。

`activeTab` 提供由用户操作触发的临时访问，不能据此认为扩展拥有所有页面和所有图片 CDN 的权限；受限制的浏览器页面也不会因此开放。依据：[Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab/)。

### 6.2 可选图片来源权限

允许在可选主机权限范围中声明可请求的 HTTPS 站点，再在用户点击获取图片时请求该图片实际来源。可选声明不等同已授权全站访问。权限请求必须在有效用户操作中发起。依据：[Chrome Permissions API](https://developer.chrome.com/docs/extensions/reference/api/permissions)。

扩展页或后台发起跨来源读取时需要相应主机权限；内容脚本仍受所在网页的同源限制，不能通过将获取操作放进内容脚本来保证下载。依据：[Chrome 跨来源网络请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)。

P0 图片获取默认不携带 Cookie 和站点认证信息，不自动处理跨来源重定向。需要登录、特殊 Referer、签名已过期或服务端反抓取要求的图片，提供保存来源或用户自行下载后加入桌面端的方式。

### 6.3 特殊页面与资源

| 情况 | P0 行为 |
| --- | --- |
| `chrome://`、`edge://`、扩展商店等受限制页面 | 不尝试强行注入；可得的普通 HTTPS 链接可作为链接保存 |
| `file://` 页面 | 默认不处理，通过桌面端加入本地文件 |
| 浏览器内置 PDF 阅读器 | 只承诺保存可取得的原始链接，不承诺提取当前页选区 |
| 登录后才能访问的普通网页 | 保存用户主动选择的标题、链接和摘录，不复制登录凭据 |
| 图片在 CDN | 单独判断实际图片来源的访问权 |
| `blob:`、`data:`、Canvas、CSS 背景图 | P0 不保证下载；优先保留来源，P1 再考虑截图或专用提取 |
| 单页应用或保存前页面已变化 | 检查固定的页面实例与 URL，提示重新采集，不混合两个页面的信息 |
| 跨域 iframe | 不承诺 DOM 访问；可用时保存浏览器直接提供的选区信息 |
| 无痕窗口 | P0 不提供采集；即使环境允许扩展在其中运行，也禁用入库动作并说明 |
| `javascript:` 等非网页目标 | 拒绝作为可打开的资料 URL |

不从密码框、表单输入值或隐藏输入字段生成“页面摘录”。不在用户未发起采集时持续读取 DOM。

## 7. 两端协同架构

### 7.1 建议架构

```text
浏览器网页
  ↓ 用户主动选择后，短时提取
内容脚本 / 浏览器上下文菜单
  ↓ 受限消息
扩展界面 + Service Worker
  ├─ 标签缓存 / 草稿 / 持久发送队列
  └─ Native Messaging
          ↓
     本地桥接程序
          ↓ 当前用户范围内的 IPC
     单实例资料服务 ← 桌面界面
          ├─ SQLite：资料、标签、备注、操作收据
          ├─ 受管理采集目录：网页图片原始副本
          └─ 可重建缓存：缩略图、预览
```

建议扩展继续采用 TypeScript，复用桌面端的标签组件、视觉令牌和协议类型；不复用直接依赖桌面运行环境的组件。桌面方案沿用 v0.1 的 Tauri 与 Rust 建议，但数据服务应从窗口生命周期中分离。

### 7.2 Native Messaging 的选择

浏览器通过注册的本地主机与原生程序交换消息；内容脚本不能直接使用该接口，必须由扩展后台转发。本地主机配置以明确的扩展来源限制访问。依据：[Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)。

本项目优先采用它来避免首版额外暴露常驻本地 HTTP 端口。自定义 URL 协议可在后续承担“打开资料”入口，但不承担正文、标签和图片的可靠传输。

若技术验证改用本地 HTTP，需重新设计端口发现、配对认证、来源校验、回环地址限制与请求重放处理。不能直接将某个 `localhost` 端口视为天然可信；这不是当前 P0 默认方案。

### 7.3 三个本地组件的职责

| 组件 | 职责 | 生命周期 |
| --- | --- | --- |
| 桌面界面 | 浏览、编辑、预览、设置、用户确认 | 按用户打开和关闭 |
| 桥接程序 | 处理浏览器通信、校验来源、转发固定业务命令 | 每条浏览器连接可有独立进程 |
| 资料服务 | 唯一数据库写入者，管理事务、文件和备份 | 单用户单实例，可按授权在后台运行 |

桥接程序不直接写数据库。Chrome、Edge 与多个浏览器配置可以同时建立桥接进程，最终汇聚到同一个资料服务。

Windows 建议用限定当前用户的命名管道连接本地组件，并通过单实例锁处理启动竞争。限制远程管道连接；记录与校验服务实例身份，防止误连到另一用户或另一个文件库。此方案用于进程边界与常规访问控制，不宣称能抵御已经控制当前用户账号的恶意程序。

### 7.4 桌面关闭时的行为

| 场景 | 行为 |
| --- | --- |
| 主窗口关闭，资料服务仍在 | 正常入库，扩展显示已连接 |
| 服务未运行，用户允许浏览器唤起后台 | 桥接程序启动当前用户的服务，再重放待交付操作 |
| 用户未允许后台唤起 | 扩展暂存，提示打开桌面软件后继续 |
| 用户主动暂停浏览器接收 | 停止自动交付和唤起，保留队列，等待用户恢复 |
| 备份恢复或迁移占用写入锁 | 返回维护状态，扩展按退避策略等待 |
| 软件未安装或桥接注册缺失 | 提供安装或修复指引，不能显示为普通搜索无结果 |

“允许浏览器唤起后台服务”在首次连接时说明，并可在桌面设置中关闭。点击“暂停浏览器接收”后，桥接程序必须尊重持久暂停状态，不通过再次启动服务绕过用户选择。

### 7.5 首次配对

1. 桌面安装程序注册 Chrome 与 Edge 所需的桥接配置。
2. 用户安装扩展，点击“连接拾签”。
3. 桥接程序校验实际扩展来源；仅允许开发环境明确配置的开发 ID 或发布环境明确配置的正式 ID。
4. 首次连接在桌面侧展示浏览器连接请求、目标文件库和可用能力，由用户确认。
5. 本地服务签发与客户端安装实例及文件库绑定的随机凭据；扩展在受信任上下文中保存。
6. 后续连接验证凭据、资料库身份和版本，再开放搜索、采集和资料定位命令。

同一扩展的每个浏览器配置有独立 `client_id`。这个 ID 是安装身份标记，不能单独作为认证凭据。浏览器名称、配置名称也只是展示信息，不作为可信身份声明。

解除配对立即停止该客户端继续读写，保留其尚未交付的队列供用户处理。凭据不得进入网页 DOM、内容脚本消息、日志或资料备份。

### 7.6 安装与浏览器差异

Native Messaging 依赖随桌面软件安装的桥接组件，单独安装浏览器扩展不会自动拥有本地程序。Chrome 与 Edge 的主机注册及扩展 ID 应分别验证，正式商店 ID 可能不同于开发时 ID。依据：[Microsoft Edge Native Messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)。

安装器负责注册、升级和卸载桥接组件；扩展不尝试自行写注册表。优先采用用户级安装，是否支持系统级安装另行决定。

## 8. 通信契约与可靠交付

### 8.1 协议版本与消息字段

传输遵循浏览器 Native Messaging 的标准消息封装。本文用字段表描述业务协议，不提供原始配置或消息对象示例。

| 字段 | 用途 |
| --- | --- |
| protocol_major / protocol_minor | 协议兼容协商，主版本不兼容时拒绝写入 |
| request_id | 一次请求响应的关联标识 |
| operation_id | 一次逻辑写操作的稳定标识，重试时保持不变 |
| client_id | 当前扩展安装实例 |
| library_id | 目标文件库身份 |
| library_epoch | 当前库运行世代；恢复或重建后变化 |
| capability / action | 固定业务命令，不接受任意代码或系统命令 |
| expected_version | 编辑已有资料时用于冲突检测 |
| payload_hash | 校验同一操作标识对应内容没有改变 |
| result_status | 已提交、处理中、需用户处理或错误等明确结果 |

首次握手返回资料库身份、当前世代、能力列表、协议版本、媒体和消息大小限制。客户端不可只比较软件版本字符串来判断功能是否可用。

`library_epoch` 由当前安装环境持久化维护，恢复完成后生成新值，不从备份中原样恢复。文件库世代变化后，扩展刷新缓存并暂停旧队列，要求用户确认将哪些任务重新提交到恢复后的库。

### 8.2 应用层大小限制

Native Messaging 对消息尺寸存在限制，原生端发往浏览器的单条消息上限为 1 MB。应用另外统一设置更低的 **256 KiB 编码后消息上限**，方便两端实现和测试。依据：[Chrome Native Messaging 协议](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)。

媒体建议按 128 KiB 原始字节分块传输，编码后仍须检查消息上限。搜索摘要分页返回；不把图片、全文或完整资料库塞入一条消息。协议输出通道仅传输协议消息，诊断写入独立日志。

以下均为本项目初始限制，M0 验证后可以调整：

| 项目 | 初始限制 |
| --- | --- |
| 单图片编码体积 | 10 MiB |
| 单图片解码像素 | 40 MP，仍复用桌面端安全解码上限 |
| 单摘录 | 20,000 个用户可见字符 |
| 单备注 | 10,000 个用户可见字符 |
| 单资料标题 | 500 个用户可见字符 |
| 单 URL | 8 KiB 编码后长度，超出时保留草稿并提示 |
| 每次搜索返回 | 初始 20 条摘要，同时遵守总消息尺寸限制 |
| 暂存未交付媒体总量 | 50 MiB，实际配额不足时提前阻止新保存 |
| 暂存未交付资料数 | 1,000 条，同时受实际存储配额约束 |

浏览器暂存上限是产品预算，不是浏览器提供的容量保证。获取不到完整图片时只存获取意图，不能记为拥有离线图片。

### 8.3 核心命令

| 命令 | 输入摘要 | 输出摘要 | 规则 |
| --- | --- | --- | --- |
| `bridge.hello` | 协议范围、客户端身份与配对凭据 | 版本、能力、库身份和限制 | 必须先于业务写入 |
| `tags.snapshot` | 分页游标、已知目录版本 | 标签快照、目录版本、下一页 | 建立同一版本下的完整快照 |
| `resources.lookup` | 资料类型、规范化目标 | 现有候选记录、版本或未发现 | 仅在用户发起的采集流程调用 |
| `capture.prepare` | 稳定操作 ID、资料元信息、标签与备注、媒体意图 | 暂存任务与上传令牌或已有操作结果 | 校验来源、库世代、大小与身份 |
| `capture.chunk` | 上传令牌、块序号、块校验、字节 | 已接收范围或错误 | 重复块幂等，错误内容拒绝 |
| `capture.status` | 操作 ID | 暂存进度、缺块、已提交资料 ID | 断线后的第一查询入口 |
| `capture.commit` | 操作 ID、内容摘要、已完成媒体声明 | 资料 ID、版本、保存类型、服务提交序号 | 完成事务后才返回已提交 |
| `capture.cancel` | 操作 ID | 已取消、尚未提交或已经提交 | 不把已经入库的资料悄悄删除 |
| `resources.search` | 关键词、标签、类型、游标 | 限量摘要、下一页 | 共用桌面搜索实现 |
| `resources.patchTags` | 资料 ID、差量标签、预期版本 | 新版本或冲突 | 首版仅连接状态下编辑已有资料 |
| `resources.saveNote` | 资料 ID、完整备注、预期版本 | 新版本或冲突 | 不默默覆盖桌面端的新备注 |
| `desktop.revealResource` | 资料 ID、当前可信界面的操作上下文 | 定位结果 | 不能由页面脚本自行触发 |
| `resources.openLocal` | 资料 ID、当前可信界面的操作上下文 | 打开结果 | 本地服务解析路径，扩展不传 shell |

P0 使用带版本的分页全量标签快照，优先保证正确性。P1 才增加增量变更日志。收到标签版本变化通知、重新连接或打开编辑界面时检查并刷新，断线时明确提示缓存可能过期。

分页拉取期间检测到标签目录版本变化时，丢弃未完成快照并重新获取；最后一页通过版本校验后再整体替换缓存。不能将不同版本的分页结果拼成一份看似完整的目录。

### 8.4 队列状态机

```text
草稿
  ↓ 用户保存，持久写入成功
待交付
  ├─ 未连接 / 未获取媒体 → 等待条件满足
  └─ 已连接 → 准备任务 → 上传媒体（需要时）→ 提交
                                          ↓
                                     收到提交回执
                                          ↓
                                        已送达

连接中断 → 保留稳定操作 ID → 重连后查询状态 → 续传或接受既有回执
身份变化 / 标签失效 / 冲突 → 需要用户处理
不可恢复错误 → 保留失败原因与草稿，等待用户修改或取消
```

扩展必须先持久化任务与媒体，再展示“已暂存”。磁盘或配额不足时明确失败，不能先显示成功再尝试写缓存。

### 8.5 幂等、收据与重复检测

网络重试去重与资料内容去重是不同问题：

- **操作幂等**：同一个 `client_id + operation_id` 只能提交一次，核心服务将操作收据与资料变更放在同一事务中。重试返回原结果。
- **内容重复**：两个不同操作可能采集同一网页，按第 9 节的资料规则判断是否复用。

同一操作 ID 携带不同内容摘要时拒绝处理。只要操作曾发出，就不能静默改写它的标签、备注或目标 URL；先确认原任务状态，再用新的操作表达用户修改。

提交成功但回执丢失时，扩展通过状态查询找回结果，不再次附加备注或重复生成图片。资料被移除后仍保留操作收据，旧任务重试不得复活它。

取消与提交必须通过服务端同一状态机串行决定。已取消任务不能再提交；提交已完成则返回已提交状态，由用户另行执行资料移除，不能把取消发送等同于删除已入库内容。

P0 持久保存轻量操作收据，不自动过期清理；未来清理策略必须同时定义旧操作的拒绝规则。队列是“至少一次尝试交付”，业务幂等提供每个逻辑操作只生效一次的结果，不能宣称传输过程恰好发生一次。

### 8.6 重试与浏览器生命周期

Manifest V3 后台 Service Worker 可以被终止，内存变量不能充当唯一队列；应把待交付状态放入持久存储。依据：[Chrome 扩展 Service Worker 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。

建议使用扩展来源下的 IndexedDB 保存任务与媒体 Blob，使用 `storage.local` 保存少量偏好和连接配置。不要把媒体塞入偏好存储，也不使用浏览器同步存储传输本地路径和内容。`storage.local` 有配额且默认可能暴露给内容脚本，应设置访问级别，只让可信扩展上下文读取连接信息。依据：[Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)。

重试采用有上限的退避并加入抖动，通过用户操作、启动事件和浏览器调度机会继续；不依赖常驻计时器或无意义心跳永久保活。过期的发送租约可被下一次唤醒接管，不能因“上次正在发送”永久卡住。

浏览器关闭时不能保证及时交付。卸载扩展或删除配置可能清除尚未交付内容；队列界面应始终显示待交付数量。已经进入桌面库的资料不受扩展卸载影响。

## 9. URL、重复资料与并发规则

### 9.1 URL 规范化

保留原始 URL 作为来源证据，另生成保守的去重键：规范化协议与主机大小写、默认端口等无歧义部分，保留路径大小写、查询参数及片段。

首版不自动删除营销参数、不重排重复查询参数，也不统一移除片段，因为参数和片段可能表示不同内容或单页应用路由。网页声明的 canonical 地址只保存为候选提示，不直接作为覆盖原地址或跨域合并的依据。

只允许正常 HTTP/HTTPS 资料链接；图片字节获取按第 6 节限制为公开 HTTPS。含用户名或密码的 URL 不原样入库，要求用户提供不含凭据的目标。URL 中可能影响访问的其他参数不擅自删除，日志和诊断导出应避免泄露它们。

### 9.2 不同资料的重复规则

| 类型 | P0 判定依据 | 行为 |
| --- | --- | --- |
| 网页 | 同类型、同规范化目标 URL | 复用现有资料，可补充标签和采集备注 |
| 网页图片 | 同类型、同来源页面、同图片 URL | 复用资料，可补充本地图片副本 |
| 摘录 | 同页面、规范化文本摘要、可用的前后文定位摘要 | 高一致性时复用，否则保留独立资料 |
| 本地文件 | 原文件路径与身份规则 | 继续遵守桌面端规格 |
| 图片二进制 | 完整字节 SHA-256 与长度一致 | 可以共用存储副本，但不合并不同来源的资料身份 |

无法确定是否为同一摘录时宁可保留不同资料。来源不同但图片字节相同的两次采集各自保留出处。

同一图片 URL 再次下载得到不同字节时，不覆盖原始副本。返回“来源内容已变化”，由用户选择保留已有资料或另存新版本资料。另存时将内容摘要加入变体去重键，后续查询可返回多个候选版本；每条资料仍最多一份主副本。并发采集时同一内容变体也应受唯一约束保护。

软移除资料被再次采集时，提示恢复原资料或取消，不因后台重试自动恢复。用户明确恢复时保留资料 ID 和原标注。

### 9.3 再次采集的更新语义

- 用户自定义过的标题不被新的网页标题覆盖；新来源信息进入采集记录。
- 本次新增标签与已有标签取并集，不根据一次采集表单删除原有标签。
- 新资料的采集备注写入资料备注。
- 重复资料带有新备注时，以带采集时间的附记追加，并明确反馈；不覆盖已有备注。
- 附记追加与操作收据在同一事务内完成，避免断线重试重复追加。
- 备注追加会超过长度限制时进入需用户处理状态，不截断或丢弃。

编辑已有完整备注和移除已有标签是单独的在线编辑动作，需要预期版本；不能把离线采集的附记解释为覆盖指令。

### 9.4 标签身份与冲突

已存在的标签按 ID 传输。离线时选中缓存标签，但服务端已重命名同一 ID，自动采用新名称；标签已删除时返回“标签已失效”，要求用户重选，不按旧名称偷偷重建。

离线新输入的标签名称作为“待解析名称”提交，由本地服务按统一 NFC 与大小写折叠规则原子地查询或创建。两个浏览器同时创建同名标签最终只产生一个标签 ID。

全局标签合并、删除和重命名放在桌面端，P0 扩展只创建或选择标签、修改资料关联。

已有资料版本冲突时，展示服务器新内容和本次草稿，允许用户重新应用，不使用静默最后写入者覆盖。纯新增标签可以由服务端按集合并集安全重算，但移除标签与覆盖备注必须校验版本。

### 9.5 多浏览器与文件库恢复

Chrome 和 Edge 使用各自的客户端 ID 与缓存，共享同一桌面资料库。不存在“以哪个浏览器的标签副本为主”的选择。

恢复或切换资料库后，旧队列不能自动进入新世代；应先冻结交付并让用户确认。重新配对不会自动把另一浏览器配置的队列搬过来。

## 10. 统一数据模型与迁移

### 10.1 桌面端权威实体

| 表或实体 | 关键字段 | 说明 |
| --- | --- | --- |
| `items` | id、kind、title、title_search、dedupe_key、is_favorite、created_at、updated_at、record_version、removed_at | 所有资料共同身份 |
| `files` | id、item_id、原路径与身份字段、availability、content_revision | 本地文件子实体；保留原文件 ID，item_id 唯一 |
| `web_sources` | item_id、original_url、normalized_url、source_page_url、source_domain、original_title、image_url、captured_at、canonical_candidate | 网页资料的来源，不要求本地路径 |
| `excerpts` | item_id、quote_text、text_search、prefix_text、suffix_text、anchor_hint、anchor_status | 摘录内容与定位提示 |
| `tags` | id、name、name_key、record_version、updated_at | 沿用统一标签实体 |
| `item_tags` | item_id、tag_id、created_at | 替代只关联文件的关系表 |
| `item_notes` | item_id、body、body_search、record_version、updated_at | 统一备注 |
| `capture_events` | id、item_id、client_id、operation_id、source_info、captured_at | 采集来源和操作追踪，不存浏览历史 |
| `managed_assets` | id、relative_path、sha256、byte_length、mime、width、height、state | 用户主动保存的不可随缓存清理的原始副本 |
| `item_assets` | item_id、asset_id、role | 将本地图片副本关联到资料，P0 一份主副本 |
| `operation_receipts` | client_id、operation_id、payload_hash、item_id、result_status、commit_sequence、created_at | 幂等结果；联合唯一键 |
| `ingest_sessions` | operation_id、client_id、library_epoch、asset_manifest、received_ranges、state、expires_at | 可恢复的上传暂存任务 |
| `paired_clients` | client_id、allowed_origin、credential_hash、capabilities、revoked_at | 配对记录，凭据仅存校验形式 |
| `library_meta` | library_id、schema_version、tag_catalog_version、last_commit_sequence | 文件库身份、模式和变更序号 |

当前安装的 `library_epoch` 与本地通信秘密存储在安装状态中，不随资料备份直接恢复。`paired_clients` 不写入可分享的资料备份；换机恢复后重新配对。

网页图片本地副本通过 `managed_assets` 表示，不再伪造一条用户导入的 `files` 记录。对用户而言仍是一条资料，避免搜索和标签计数翻倍。

### 10.2 关系与约束

```text
items ── item_tags ── tags
  ├─ item_notes
  ├─ files                 仅本地文件
  ├─ web_sources           网页、网页图片、摘录
  ├─ excerpts              仅文字摘录
  ├─ capture_events
  └─ item_assets ── managed_assets
```

- 文件与网页共享标签规则、收藏状态和软移除规则。
- `(item_id, tag_id)` 唯一，所有引用启用外键。
- 对适用类型的资料去重键建立数据库约束，不能仅依靠前端先查后建。
- 标签使用量计算未移除资料数，不计算底层附件数量。
- `files` 中被提升到 `items` 的标题、收藏、移除和备注字段不继续独立写入，避免双重权威。
- 原文件可用性只适用于本地文件；远程链接默认“未检查”，不会后台遍历请求所有收藏链接。
- 所有本地副本使用受管理目录中的相对路径，不接受网页提供的磁盘绝对路径。

### 10.3 v0.1 数据迁移步骤

1. 暂停写入并创建一致性备份，验证可恢复。
2. 为每条原文件记录创建 `local_file` 资料，建议沿用原文件 ID 作为资料 ID；保留旧文件 ID。
3. 将标签关联迁入 `item_tags`，备注迁入 `item_notes`，收藏、加入时间与软移除状态迁入 `items`。
4. 为 `files` 建立唯一的 `item_id` 关联，保留路径与文件身份信息。
5. 创建网页、摘录、托管图片、配对、上传任务和操作收据表。
6. 校验迁移前后记录数、标签关联数、备注内容和软移除数量一致。
7. 将旧文件业务接口改成统一资料服务的适配层；原 `files.query` 只查询 `local_file`，新 `resources.search` 查询全部类型。
8. 完成后更新模式版本并重新生成当前世代。失败时回滚并保留原库。

不得通过清空数据库重新初始化来替代迁移。旧版应用检测到较新的模式版本时只提示升级，不尝试按旧结构写入。

### 10.4 扩展本地存储

| 数据 | 保存位置 | 生命周期 |
| --- | --- | --- |
| 采集草稿、不可变操作、暂存媒体 | 扩展来源 IndexedDB | 持久保存，送达并确认后清理媒体 |
| 标签缓存与库版本 | IndexedDB 或小型本地存储 | 连接后校验；库世代变化时失效 |
| 客户端身份、配对配置、界面偏好 | 受信任上下文的本地存储 | 配对或安装生命周期 |
| 当前进度、页面实例句柄 | 内存，必要状态另行持久化 | 不作为唯一交付凭据 |

扩展不是完整资料库镜像。成功交付后可保留最近 100 条采集摘要用于快速查看，媒体在确认桌面提交后删除；这不影响桌面端的原始副本。

## 11. 图片入库、受管理目录与备份升级

### 11.1 图片传输与提交顺序

1. 用户明确选择保存图片到本地，扩展取得所需来源权限。
2. 扩展流式读取并执行体积限制，取得完整字节、摘要和格式信息；必要时暂存在 IndexedDB。
3. 桥接程序根据已配对客户端和操作 ID 建立上传任务，返回不可猜测的上传令牌。
4. 本地服务将分块写入自己的暂存目录，校验块序号、大小和摘要；重复块内容一致才接受。
5. 收齐后校验完整 SHA-256、实际字节长度、图片文件签名和解码像素，不仅相信文件扩展名或远端 Content-Type。
6. 服务生成自己的文件名，在受管理根目录内将暂存文件落到最终路径，避免覆盖用户已有文件。
7. 数据库事务一次提交资料、标签、备注、来源、副本引用与操作收据。
8. 事务成功后返回“图片已保存到本地”；扩展确认回执后清除暂存媒体。

文件系统与数据库不能被假装成一个天然的原子事务：最终文件已落盘而数据库提交前崩溃时，启动恢复程序依据暂存记录辨认孤立副本；数据库已提交后，不得将其当成无主缓存删除。

上传中止不创建假成功资料。用户改为只保存来源时，先查询原操作是否已提交；确认未提交后取消并新建来源保存操作。

### 11.2 目录与删除规则

建议资料库目录分为：元数据库、`assets` 原始采集副本、`staging` 上传暂存、`cache` 可重建预览、恢复前备份。

- 文件名由服务端生成，网页标题只参与展示，不直接组成磁盘路径。
- 所有写入路径解析后必须位于既定目录，拒绝路径穿越与平台保留名问题。
- 同一字节副本可被多个资料引用，移除单个资料不删除仍被引用的副本。
- P0 的“移除资料”仍是软移除，不提供自动永久删除托管原始副本。
- 只清理过期且未提交、无有效上传租约的暂存文件；不能因一次连接断开立刻删掉可续传内容。
- 缓存清理按钮明确排除 `assets`。

### 11.3 完整备份与轻量备份

| 方式 | 内容 | 推荐用途 |
| --- | --- | --- |
| 完整资料备份，默认 | 一致性元数据库、受引用的托管原始副本、清单与校验和 | 换机、长期保存与恢复 |
| 轻量标注备份，可选 | 元数据库和副本清单，不含图片字节 | 快速保留组织关系；必须标明无法恢复图片本体 |

两种方式都不自动包含用户外部目录中的原文件。完整备份包含软移除记录仍引用的副本，以保留再次加入和恢复所需内容。

导出数据库副本时剔除配对凭据、客户端授权状态和未完成上传任务；保留资料来源及幂等收据。不得直接把运行数据库和本机连接秘密不加区分地打包。恢复后使用新的配对状态和库世代。

备份格式升级，旧版恢复器应拒绝不理解的新版包。源图片副本以不可变内容保存，备份先取得数据库快照和受引用副本清单，再固定这些副本直到归档结束，避免快照与文件集合错位。

恢复时在临时目录校验数据库和图片，先保护当前库，再执行可回滚切换。原始文件引用可能需要重新关联，受管理副本则根据新根目录解析相对路径。

数据库和资产目录一起切换成功后更新当前库世代，扩展队列进入复核状态。恢复失败时同时回滚数据库和资产映射，不能保留指向不存在副本的半完成状态。

浏览器中尚未交付的队列不在桌面备份内；备份完成页只说明服务已经收到的数据范围，不声称所有浏览器暂存均已包含。

## 12. 安全边界、隐私与故障反馈

### 12.1 区分网页内容与扩展控制指令

网页提供的标题、选区、图片地址和 canonical 均为不可信数据，不能作为执行指令。

内容脚本仅可返回当前采集任务需要的有限字段。Service Worker 校验消息来源、标签页、页面实例、框架和短期任务标识；不能因为消息带了某个动作名称就转发任意本地命令。

搜索资料库、读取标签、打开本地文件和修改标注，只接受扩展自身受信任界面的明确操作。不得将资料库搜索结果、配对凭据、本地路径或标签列表返回网页脚本。

P0 不开放网页可调用的外部消息接口，也不通过页面 `postMessage` 暴露通用本地文件能力。内容提取与资料库查询使用不同的命令白名单。

### 12.2 本地与网络边界

- 本地端不接受网页指定的磁盘路径、SQL、可执行命令或动态脚本。
- 媒体上传令牌绑定客户端、库世代、操作和字节上限，不能用于其他任务。
- 凭据、原始摘录和备注正文不写入普通诊断日志。
- 资料标题和网页内容以文本渲染，不作为 HTML 直接插入扩展或桌面界面。
- P0 不自动加载所有收藏网页的 favicon、远端图片预览或可用性检查，避免浏览资料库时触发未知网络请求。
- 图片源请求限定为用户确认的目标，采用明确的体积、超时与重定向策略；不提供内容脚本可调用的通用网络代理。
- 内网图片采集不在 P0 支持范围；至少拒绝本地回环、已知私有 IP 字面量与本机保留主机名，不把此筛选宣传为对所有网络环境的完整隔离。

### 12.3 首版状态与错误文案

| 状态或错误 | 建议反馈 | 用户可做什么 |
| --- | --- | --- |
| 桌面软件未安装 | 尚未找到拾签桌面连接组件 | 安装桌面软件，或先保留草稿 |
| 桥接组件损坏或失效 | 本地连接组件需要修复 | 打开桌面设置中的修复入口 |
| 尚未配对 | 需要连接当前资料库 | 发起配对 |
| 用户暂停接收 | 浏览器接收已暂停 | 打开桌面端恢复接收 |
| 暂时断线 | 已暂存，连接后继续 | 查看队列、重试或取消 |
| 图片权限被拒绝 | 暂未获得该图片来源的读取权限 | 重新授权或仅保存来源 |
| 图片获取失败 | 图片尚未保存到本地 | 重试、保存来源或自行下载 |
| 标签已删除 | 一个所选标签已失效 | 重新选择标签 |
| 资料版本冲突 | 资料已在其他位置修改 | 查看最新内容，再应用草稿 |
| 浏览器存储不足 | 暂存空间不足，尚未保存 | 先交付或清理已确认不需要的队列 |
| 数据库不可写 | 桌面资料库暂时无法写入 | 保留队列并修复本地问题 |
| 协议版本不兼容 | 扩展与桌面版本不匹配 | 更新对应组件 |
| 资料库已恢复 | 文件库状态已变化，待交付内容需要复核 | 确认目标库与待提交项目 |
| 已移除资料被再次采集 | 该资料已被移除 | 明确恢复或取消 |

稳定错误码建议包括：`HOST_NOT_FOUND`、`PAIRING_REQUIRED`、`CLIENT_REVOKED`、`RECEIVING_PAUSED`、`PROTOCOL_MISMATCH`、`LIBRARY_EPOCH_CHANGED`、`SOURCE_PERMISSION_REQUIRED`、`MEDIA_FETCH_FAILED`、`MEDIA_TOO_LARGE`、`QUEUE_QUOTA_EXCEEDED`、`TAG_REFERENCE_STALE`、`VERSION_CONFLICT`、`PAYLOAD_MISMATCH`、`RESOURCE_REMOVED`。

### 12.4 发布资料

商店说明与隐私说明应清楚说明：主动采集的字段、本地存储方式、图片下载涉及来源网络请求、连接桌面软件的必要性，以及暂存与成功入库的区别。

扩展的可执行代码随包发布，不从 CDN 或远端下载脚本后执行。规则与适配更新不得借“配置”执行远端代码。依据：[Chrome 对远程托管代码的说明](https://developer.chrome.com/docs/extensions/develop/migrate/remote-hosted-code)。

是否启用匿名统计为后续产品决策，P0 不预置联网统计。无须登录账户即可使用已安装的本地配套功能。

## 13. 同时开发的任务划分

### 13.1 建议工程组织

```text
apps/
  desktop/             桌面界面与窗口入口
  browser-extension/   弹窗、右键菜单、采集页、队列、搜索
services/
  library-core/        单实例本地资料服务，唯一写库入口
  native-bridge/       浏览器原生消息适配
packages/
  protocol/            协议字段、校验规则、错误码与测试样本
  ui-tokens/           色彩、间距、字体层次与标签视觉规范
tests/
  contract/            两端接口契约与异常样本
  integration/         数据、进程、传输、备份恢复
  browser-fixtures/    受控网页与跨域图片测试服务
docs/
  architecture/        决策记录、版本策略与支持矩阵
```

可以使用单仓库方便协议同步，属于建议。无论仓库如何划分，都应有唯一协议定义与兼容测试，不在两个工程内手写互相漂移的类型。

浏览器和桌面构建分别锁定依赖。共享 TypeScript 类型不能替代 Rust 边界校验；两端需用共同协议样本测试编码、长度、字段和错误行为。

### 13.2 可并行工作与依赖

| 工作线 | 主要任务 | 前置条件 | 可独立验证的结果 |
| --- | --- | --- | --- |
| 共享设计与协议 | 统一资料模型、语义、错误码、状态机、大小限制 | 产品范围确定 | 契约文档和固定样本 |
| 本地核心 | 模式升级、标签服务、采集事务、媒体落盘、收据 | 共享模型与协议 | 可由测试客户端调用的本地服务 |
| 桌面界面 | 全部资料、类型筛选、来源详情、连接设置、备份 | 协议与可替换数据接口 | 可在模拟服务下走完界面流程 |
| 浏览器扩展 | 弹窗、菜单、提取、权限、队列、搜索 | 协议与受控网页样本 | 可在模拟桥接下验证采集和状态 |
| 系统集成 | 安装注册、配对、后台启动、Chrome/Edge 兼容 | 最小桥接和服务 | 两浏览器均可稳定提交同一测试资料 |
| 验证与发布 | 故障注入、升级、备份、性能与发布包 | 可运行的端到端版本 | 可追踪的验收报告 |

模拟服务只能用于开发与测试；正式扩展不能在连接失败时悄悄切换到演示数据并显示成功。

### 13.3 开发里程碑

| 阶段 | 目标 | 出口条件 |
| --- | --- | --- |
| M0：联通验证 | 两个浏览器安装测试扩展，Native Messaging 连接本地服务；读取一次当前页并往返消息 | 确认注册、权限、版本和打包路径，固定支持矩阵 |
| M1：最小共同流程 | 网页标题＋URL＋标签从扩展进入桌面端，并能搜索找回 | 真正共享标签与数据库；重复提交只产生一次结果 |
| M2：统一资料与界面 | 本地文件、网页、摘录混合展示，完成浏览器搜索与桌面定位 | 类型与状态表达正确，桌面原功能无回归 |
| M3：图片与暂存 | 公开图片下载、分块传输、受管理副本、持久队列 | 断线、重启、回执丢失后可恢复且不重复 |
| M4：配对与可恢复性 | 多浏览器并发、库迁移、备份恢复、版本兼容 | 数据与副本完整，旧队列不会误写恢复后的库 |
| M5：首版交付 | 兼容、性能、安装升级、用户帮助和商店材料 | 全部 P0 验收通过，限制说明与实际行为一致 |

第一条必须跑通的流程是：**网页主动采集 → 选择真实桌面标签 → 本地提交 → 桌面搜索 → 打开来源。** 图片、复杂预览和侧栏都在此基础上增加。

M0 必须专门验证：Chrome 与 Edge 注册差异、正式与开发扩展 ID、Windows IPC 权限、公开 CDN 图片权限、浏览器终止后台后的队列恢复、图片消息分块。未验证的能力不可仅以 UI 原型代替完成。

## 14. 验收用例

### 14.1 采集与体验

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| B01 | 保存当前普通网页 | 标题、实际 URL、标签和备注正确进入桌面库 |
| B02 | 保存页面中的链接目标 | 目标链接与来源页面分别保存，不误存成当前页 |
| B03 | 保存后立即关闭弹窗 | 已持久化任务继续存在，不依赖弹窗进程 |
| B04 | 保存前切换标签页 | 保持原采集目标或提示重新采集，不混入新页面 |
| B05 | 单页应用路由变化 | 变化被识别，URL、标题与摘录来自同一个页面状态 |
| B06 | 同一网页连续点击保存 | 一个逻辑操作只提交一次 |
| B07 | 稍后再次收藏同一网页 | 按规则复用资料，不覆盖自定义标题和旧备注 |
| B08 | 保存图片来源 | 只显示“已保存图片来源”，不显示本地图片完成 |
| B09 | 下载公开 PNG/JPEG/WebP | 完整字节和来源入库，断网后可打开本地副本 |
| B10 | 图片来自不同 CDN | 只请求需要的来源权限，拒绝后能保留来源草稿 |
| B11 | 图片登录要求、失效、重定向或过大 | 不假报成功，提供明确降级选项 |
| B12 | 保存中文文字摘录 | 文本和段落正确，标签输入不破坏中文输入法 |
| B13 | 无法取得摘录定位信息 | 仍保存文本和来源，标注无法精确定位 |
| B14 | 浏览器搜索本地文件和网页 | 统一标签结果正确，各类型打开方式正确 |
| B15 | 未连接时搜索 | 清楚标注离线最近记录，不冒充完整库搜索 |
| B16 | 受限制页面与无痕环境 | 不尝试越过限制，不错误触发采集 |

### 14.2 可靠性、并发与迁移

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| B17 | 桌面窗口关闭 | 服务获允许运行时可保存，否则显示待交付 |
| B18 | 用户暂停接收 | 不自动唤起或继续入库，队列保留 |
| B19 | 后台 Service Worker 被终止 | 下次唤醒后读取持久状态并继续，不丢任务 |
| B20 | 浏览器关闭后重新打开 | 已持久化队列可继续，不依赖旧内存变量 |
| B21 | 图片分块中途断开 | 查询已有块后续传；重复块不会写坏文件 |
| B22 | 数据已提交但回执丢失 | 状态查询返回原资料，不重复备注或图片 |
| B23 | 同一操作 ID 携带不同内容 | 拒绝，并保留可诊断错误 |
| B24 | Chrome 与 Edge 同时创建同名标签 | 最终只有一个标签 ID，两份资料关联正确 |
| B25 | 离线选择的标签已被重命名 | 使用相同 ID 的新名称 |
| B26 | 离线选择的标签已被删除 | 提示重选，不静默恢复被删除标签 |
| B27 | 桌面端与扩展同时编辑备注 | 版本冲突可见，旧内容不覆盖新内容 |
| B28 | 本地库已经软移除采集资料 | 旧重试不会复活；主动再采集时提示恢复 |
| B29 | 文件落盘后、数据库提交前崩溃 | 不出现假成功记录；可识别和处理孤立副本 |
| B30 | 配额不足、磁盘满或数据库不可写 | 不宣称已暂存或已送达，保留可恢复信息 |
| B31 | 旧版数据库升级 | 原文件 ID、标签、备注、收藏和移除状态不丢失 |
| B32 | 完整备份在新安装中恢复 | 网页、摘录和托管图片可恢复；外部文件引用可重新关联 |
| B33 | 清理预览缓存 | 托管图片原始副本不被删除 |
| B34 | 恢复旧备份后扩展重新连接 | 检测库世代变化，旧队列先暂停复核 |
| B35 | 协议主版本不兼容 | 阻止写入，提示更新，队列不丢失 |
| B36 | 解除某个浏览器的配对 | 该配置停止读写，其他已授权配置不受影响 |

### 14.3 边界与安装

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| B37 | 恶意网页伪造本地打开或搜索消息 | 不得到资料库结果或本地操作能力 |
| B38 | 标题含 HTML、图片名含路径穿越 | 按文本展示，写入保持在受管理目录 |
| B39 | 媒体扩展名与内容不符 | 按实际格式校验，不能当作合法图片执行 |
| B40 | 配对凭据与本地文件信息 | 不出现在网页脚本、DOM 或普通日志中 |
| B41 | Chrome / Edge 正式安装与升级 | 对应扩展 ID、主机注册和版本协商正常 |
| B42 | 卸载浏览器扩展 | 桌面已提交资料和托管副本保持完整 |
| B43 | 相同字节图片来自两个来源 | 可复用字节副本，但两份来源资料均保留 |
| B44 | 标签全量快照期间发生修改 | 检测版本变化并重取，不能混合版本后当成完整目录 |
| B45 | 轻量备份恢复 | 明确图片本体未包含，状态与清单准确 |
| B46 | 两个浏览器同时尝试启动服务 | 最终单一写库服务，所有客户端连接到正确库 |

### 14.4 测试方式

原桌面端 A01～A28 仍需通过；涉及统一实体、搜索范围和完整备份的预期按本文更新。

测试使用受控网页样本，覆盖不同域名的图片、重复 URL、SPA 路由、选区、iframe、损坏媒体和受限响应。网页内容测试与原生进程测试分层，不能仅用模拟桥接证明真实安装可用。

故障注入覆盖：浏览器后台终止、桥接退出、服务退出、回执丢失、数据库写入失败、磁盘满和恢复中断。使用专用测试资料库，不操作用户真实工作文件。

## 15. 性能目标与支持矩阵

以下是建议预算，不是已经实现的指标。基准沿用桌面端的 Windows、本地 SSD、16 GB 内存，并使用 10,000 条混合资料、500 个标签和平均 5 个标签关系的样本。

| 项目 | 建议目标 | 说明 |
| --- | --- | --- |
| 弹窗本地初始内容 | 通常 300 ms 内可交互 | 不等待桌面启动或网络请求 |
| 已连接时网页元数据入库 | p95 ≤ 1 秒 | 不含首次配对、冷启动和媒体下载 |
| 搜索首屏摘要 | 热缓存 p95 ≤ 500 ms | 包含扩展、本地通信与查询 |
| 保存后桌面列表更新 | 通常 1 秒内 | 不等待缩略图完成 |
| 长时间无操作 | 不持续读取页面、不维持无用途高频轮询 | 通过实际事件与可恢复状态工作 |
| 图片下载与传输 | 有进度、可取消、可恢复 | 不对外部网络速度作承诺 |

兼容矩阵在 M0 固定具体版本，发布前用目标稳定版复验。Chrome 与 Edge 分别验证权限、菜单、后台恢复、Native Messaging 和安装流程；不能以两者同属 Chromium 为由省略验证。

最低浏览器版本由实际使用 API 与测试结果决定，不在文档中凭猜测写一个版本号。Firefox 和 Safari 另开适配任务，不纳入首版完成条件。

### 16.2 建议默认值

| 决策 | 建议 | 影响 |
| --- | --- | --- |
| 网页插件的含义 | 浏览器扩展 | 若实际指嵌入网站的组件，架构需要重新设计 |
| 首发浏览器 | Chrome 与 Edge | 共享大部分代码，但分别验收和配置 ID |
| 首发系统 | Windows 11 x64 | 与桌面端原建议一致 |
| 核心采集内容 | 链接、公开图片、文字摘录 | 覆盖常见资料场景，限制全文阅读复杂度 |
| 默认网页保存形式 | 保存链接与标注 | 整页离线阅读放到后续 |
| 图片保存形式 | 用户明确选择下载本地或只存来源 | 文案必须与真实结果一致 |
| 权威数据源 | 桌面本地资料库 | 扩展仅保留有限缓存与未交付队列 |
| 本地通信 | Native Messaging | 需要随桌面软件安装桥接组件 |
| 扩展界面 | 弹窗＋右键菜单＋独立管理页 | 侧栏在下一阶段扩展 |
| 云服务 | 首版不需要 | 网络仅用于用户主动选择的来源获取等操作 |
