## 使用流程

### 文件夹标签

默认开启。导入 `D:\素材\海报\封面.png` 时，自动添加 **海报** 标签。

- 采用每个文件的直接父文件夹名称，不会把整条路径拆成标签。
- 递归导入时，分别使用每份文件自己的父文件夹。
- 标签池已有同名标签时直接复用，不另建重复标签。
- 自动关联显示“文件夹”记号；若原来已经手工添加同一个标签，保留其手工来源。
- 在“偏好设置 → 文件夹自动标签”可开关，并为已有文件补齐标签。
- 关闭只影响后续操作，已有标签保留；重复补齐不重复添加。
- 超过 40 字符的文件夹名使用前 31 个字符、一个省略号和 8 位摘要，避免不同长名称截断后混为一项。
- 从盘符根目录导入、没有父文件夹名称时跳过文件夹标签。
- 在拾签中重新关联到新位置时，更新自动文件夹标签，保留其他来源标签。

第一版没有后台文件系统监控：在资源管理器中移动或重命名原文件，仍需使用现有“重新关联”功能。手工重命名一个文件夹标签后，再次补齐会重新按实际文件夹名称匹配。

### 启用 AI

AI 默认关闭，不预置云服务、不发送用户文件。在“偏好设置 → AI 自动标注”填写：

1. 服务地址：兼容 Chat Completions 的接口基础地址，例如本机 Ollama 的 `http://localhost:11434/v1`，或自己选择的 HTTPS 服务地址。
2. 模型名称：填写该服务实际提供的模型；图片识别必须使用视觉模型。
3. API Key：按服务要求填写，本机不要求认证时可以留空。
4. 决定是否允许 AI 创建新标签。
5. 阅读发送内容说明，勾选启用，再保存设置。
6. 点击“测试连接”。测试只发送固定的连接测试文本；成功不代表模型支持图片，需要额外用合成图片或获准文件验证。

采用现有标签池优先的识别顺序：

```text
新文件导入
  → 本地添加文件夹标签
  → AI 已启用：加入持久化队列
  → 提取图片预览或文档正文摘录
  → 模型匹配已有标签，最多建议 5 个
  → 没有合适标签且允许新建：创建新标签
  → 校验响应、文件版本和任务令牌
  → 保存 AI 来源、模型、依据、时间与确认状态
```

语义上优先复用已有标签由模型判断；完全同名的标签由本地规范化和数据库约束保证复用。第一版没有独立语义向量索引，模型仍可能产生近义标签，需要后续整理。

### 识别记号与后续更新

| 展示 | 含义 | 再次识别的行为 |
| --- | --- | --- |
| 文件夹 | 根据直接父文件夹自动关联 | 保留 |
| ✦ AI | 由 AI 给这份文件添加，尚未确认 | 可以替换 |
| ✦ AI ✓ | AI 添加后已人工确认 | 保留 |
| AI 新建 | 该标签最初由 AI 创建，显示在标签池/标签管理中 | 可正常重命名或删除 |
| 普通标签 | 手工添加 | 保留 |

**标签的创建来源与文件上的关联来源分开存储。** 例如，已有的“参考素材”标签被 AI 添加给一张新图时，这次关联仍显示 AI 记号；用户手工选择一个“AI 新建”的池内标签时，该次关联按手工标签处理。

- 文件详情中可查看 AI 任务状态、失败原因，点击“AI 识别 / 重新识别”。
- 多选文件后可以批量加入识别队列，每批最多 1000 份。
- 在未确认 AI 标签旁点击勾选按钮，确认后保留来源及识别依据。
- 重新识别只更新该文件**未确认的 AI 标签**；保留手工标签、文件夹标签、已确认 AI 标签。
- 在标签管理里重命名/删除标签；移除标签和确认操作沿用有版本保护的撤销机制。
- 图片卡片显示轻量的 AI 角标；详情、列表和标签池显示具体来源。
- 后台刷新保留已经加载的文件页和当前选择，已用超过 100 个文件的合成界面场景验证。

删除一个未确认 AI 标签后，下一次重新识别仍可能再次建议它。第一版没有“永不再推荐”排除规则。

## 支持范围与限制

| 文件 | 分析依据与限制 |
| --- | --- |
| JPEG / PNG / WebP | 实际图片预览，最长边最多 1800 像素；需要视觉模型 |
| 纯文本 | 使用已有文本预览解码，最多发送 12,000 字符 |
| PDF | 提取正文文本，文件不超过 10 MB；扫描件、无文字 PDF 暂不支持 OCR |
| DOCX / XLSX / PPTX | 本地提取正文、共享字符串、单元格或幻灯片文字，文件不超过 30 MB；不完整还原排版、图表和公式语义 |
| DOC / XLS / PPT、其他格式 | 标记未支持，保留原文件和文件夹标签 |

不能分析的文件不会仅凭文件名生成标签。Office 解压还有条目数与 XML 总量上限。超过 1000 项的标签池暂不发送，提示精简后重试。

网络连接最多等待 10 秒，总请求超时 90 秒；响应最多 256 KB。无效结构、未知标签 ID、超过 5 项结果、文件或标签版本变化都会拒绝写入，避免覆盖用户刚做的编辑。

队列串行处理，与文件导入分开运行。程序重新打开后会重新排队上次中断的任务；失败不会无限自动重试，可手动重新识别。服务切换、关闭 AI 或取消队列后，旧响应不会落库；已经发出的请求可能仍在服务端运行和计费。

## 内容发送和密钥

发送内容是：文件名、已有标签池、图片预览或最多 12,000 字符的正文摘录。请求不包含完整本地路径。远程服务可能计费；本机服务是否继续联网取决于用户配置的服务实现。

API Key 使用 Windows DPAPI 按当前用户加密，独立保存为 `ai-key.dpapi`，不写入前端持久化存储、标注数据库或备份。设置接口仅返回是否已保存密钥。更换服务地址时，未重新填写密钥会清除旧密钥，避免误发给其他服务。

模型输出仅作为标签数据解析；文件内容和标签名不会作为程序指令执行。不会替用户删除、移动或修改原文件。

实现参考：[OpenAI Chat Completions 接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[图片输入说明](https://developers.openai.com/api/docs/guides/images-vision)、[Ollama OpenAI 兼容接口](https://docs.ollama.com/api/openai-compatibility)。兼容接口并不保证所有服务和模型均已实测，本次只进行了合成内容的本机模拟接口验证。

## 数据结构与恢复

- 数据库升级为 schema 2。
- `tags.created_by` 记录标签创建来源。
- `file_tags.source` 记录一次关联的来源，`ai_meta` 保存模型、依据、时间和人工确认状态。
- `ai_jobs` 持久化识别状态，令牌防止旧请求覆盖新请求。
- 旧 schema 1 打开前生成 `backups/before-auto-tags-schema-v1.sqlite`，旧关联迁移为手工来源。
- 标注备份包含来源和确认状态；导出排除 AI 服务配置，不包含密钥。
- 恢复任意受支持备份时重新清除 AI 配置、取消待处理任务，用户自行配置和启用后才分析内容。
- 支持恢复 v0.2.2 的 schema 1 备份。v0.2.2 程序不能直接读取 schema 2，回退旧程序应使用升级前备份。
- 原文件始终需要独立备份。目录标签补齐和 AI 自动更新暂不提供整批一键撤销；重要整理前可导出标注备份。
